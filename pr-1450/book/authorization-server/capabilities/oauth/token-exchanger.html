Token Exchanger

Covers authorization-server-rust/src/domain/capabilities/oauth/token_exchanger.rs

POST /oauth/token is where an app turns what it was given into an access token it can call the FHIR server with. It has three ways in: an authorization code the Owner’s approval issued, a device request the Owner approved, or a refresh token from an earlier exchange. The token exchanger runs all three, always for an app that has authenticated.

Every exchange has the same spine. The app must be registered for the grant type it uses, checked before any scope opens, so a refused app spends nothing. Then, inside a write scope: obtain the redemption proof from the Redemption authority, load the signing key, start or rotate the refresh family through the refresh family writer, and sign the token through the access token minter. The proof is the hand-off between checking and writing, so a token is never minted for a grant that didn’t redeem.

Signing runs inside the scope, so a signing failure undoes the exchange: the code stays unspent, the device request unclaimed, the refresh token unrotated, and the app can try again. A refusal is different. Some refusals must keep what they wrote (the spent code of a failed redemption, the stamped poll of a device that polled too early, the ended family of a replayed refresh token), so a refusal comes back inside the scope’s answer, and the scope commits.

The tests exchange through an exchanger over a fresh fake, with codes issued for a fixed PKCE verifier.

exchange_refresh_token

An epoch bumped between the two scopes doesn’t stop this one rotation, as the epoch isn’t read again; but the family still began before the epoch, so its next refresh is refused.

Trade a live refresh token for a fresh access token and the refresh token’s successor (RFC 6749 §6, OAuth 2.1 rotation). The family keeps its scopes and absolute deadline — rotation never extends its life.

The one exchange with two scopes. A read scope validates the token, its client’s revocation epoch included: the epoch lives on the revocation store, another connection to the same file, so reading it under our write lock could stall both connections for the busy timeout. The write scope then re-validates the store-only facts, since the family may have ended between the two, rotates, and mints. An epoch bumped between the two scopes doesn’t stop this one rotation, as the epoch isn’t read again; but the family still began before the epoch, so its next refresh is refused.

Errors

TokenExchangeError::UnauthorizedGrantType, the validation’s InvalidGrant, a replay (RefreshTokenReplayed, after which the family is revoked), or a minting / store failure.

#![allow(unused)]
fn main() {
pub(crate) fn exchange_refresh_token(
    &self,
    authenticated_client: &AuthenticatedClient,
    presented_refresh_token: &str,
    now: DateTime<Utc>,
) -> Result<IssuedTokens, TokenExchangeError> {
    ensure_grant_type_allowed(authenticated_client, AllowedGrantType::RefreshToken)?;
    let validated_refresh_token = self.store.read(|tx| {
        ValidatedRefreshToken::validate(
            tx,
            self.revocation.as_ref(),
            authenticated_client,
            presented_refresh_token,
            now,
        )
    })?;
    self.store.write(|tx| {
        self.rotate_refresh_token_in(tx, authenticated_client, validated_refresh_token, now)
    })?
}
}

fn main() {
fn a_refresh_exchange_rotates_and_a_replay_revokes_the_family() {
    let exchanger = exchanger();
    seed_fixture_browser_session(&exchanger.store);
    let client = authenticated(&exchanger.store, "app", &AllowedGrantType::ALL);
    let plain = issue_code(&exchanger.store, "app", &["openid", "offline_access"]);
    let now = Utc::now();
    let first = exchanger
        .exchange_authorization_code(
            &client,
            &PresentedAuthorizationCode {
                code: &plain,
                code_verifier: VERIFIER,
                redirect_uri: "https://example.com/cb",
            },
            now,
        )
        .unwrap()
        .refresh_token
        .unwrap();

    let rotated = exchanger
        .exchange_refresh_token(&client, &first, now)
        .expect("rotates");
    let successor = rotated.refresh_token.expect("successor issued");
    assert_eq!(rotated.granted_scopes, ["openid", "offline_access"]);

    let replay = exchanger.exchange_refresh_token(&client, &first, now + Duration::seconds(1));
    assert!(matches!(
        replay,
        Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::RefreshTokenReplayed { .. }
        ))
    ));
    let after_revoke =
        exchanger.exchange_refresh_token(&client, &successor, now + Duration::seconds(2));
    assert!(matches!(
        after_revoke,
        Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::RefreshTokenExpired
        ))
    ));
}
}

redeem_code_in

exchange_authorization_code’s flow, inside its write scope tx. A refusal is the inner Err, so the scope keeps the spent code (and any family a replay ended).

#![allow(unused)]
fn main() {
fn redeem_code_in(
    &self,
    tx: &mut impl GrantTx,
    authenticated_client: &AuthenticatedClient,
    presented: &PresentedAuthorizationCode<'_>,
    now: DateTime<Utc>,
) -> ExchangeOutcome {
    let redeemed_code =
        match RedeemedAuthorizationCode::redeem(tx, authenticated_client, presented, now)? {
            Ok(redeemed_code) => redeemed_code,
            Err(refusal) => return Ok(Err(refusal)),
        };
    let redemption = GrantRedemption::AuthorizationCode(&redeemed_code);
    let (minter, refresh_token) = self.prepare_issuance(tx, redemption, now)?;
    issue(
        &minter,
        TokenEntitlement::AuthorizationCode(&redeemed_code),
        redemption.granted_scopes(),
        redeemed_code.patient(),
        refresh_token,
    )
}
}

rotate_refresh_token_in

exchange_refresh_token’s write half, inside its write scope tx: re-validate the token validated in the read scope, rotate it, and mint. A refusal is the inner Err, so the scope keeps a replayed family’s end.

#![allow(unused)]
fn main() {
fn rotate_refresh_token_in(
    &self,
    tx: &mut impl GrantTx,
    authenticated_client: &AuthenticatedClient,
    validated_refresh_token: ValidatedRefreshToken,
    now: DateTime<Utc>,
) -> ExchangeOutcome {
    let validated_refresh_token =
        match validated_refresh_token.revalidate(tx, authenticated_client, now) {
            Ok(validated_refresh_token) => validated_refresh_token,
            Err(TokenExchangeError::Store(error)) => return Err(error.into()),
            Err(refusal) => return Ok(Err(refusal)),
        };
    let minter = AccessTokenMinter::with_active_key(tx, &self.server_origin, ACCESS_TOKEN_TTL)?;
    let successor =
        match RefreshFamilyWriter::within(tx).rotate(&validated_refresh_token, now)? {
            Ok(successor) => successor,
            Err(refusal) => return Ok(Err(refusal)),
        };
    issue(
        &minter,
        TokenEntitlement::RefreshToken(&validated_refresh_token),
        validated_refresh_token.granted_scopes(),
        validated_refresh_token.patient(),
        Some(successor),
    )
}
}

prepare_issuance

Load the signing key, then start redemption’s refresh family if the grant earned one, inside the exchange’s scope tx.

#![allow(unused)]
fn main() {
fn prepare_issuance(
    &self,
    tx: &mut impl GrantTx,
    redemption: GrantRedemption<'_>,
    now: DateTime<Utc>,
) -> Result<(AccessTokenMinter<'_>, Option<String>), TokenExchangeError> {
    let minter = AccessTokenMinter::with_active_key(tx, &self.server_origin, ACCESS_TOKEN_TTL)?;
    let refresh_token = if redemption.is_refresh_token_earned() {
        Some(RefreshFamilyWriter::within(tx).start_family(redemption, now)?)
    } else {
        None
    };
    Ok((minter, refresh_token))
}
}
