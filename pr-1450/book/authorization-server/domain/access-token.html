An access token is what an app shows the FHIR server to be let in. It is a JWT the server signs with its active signing key, and it states everything the server decided: which app it was issued to, the scopes it carries, the SMART patient, and the browser session it was earned under. Whoever holds the token has that access until it expires or is revoked, so it is short-lived, and each one carries an id of its own so it can be revoked alone.

This page is the token as a value: its claims, minting one, and checking a presented one’s signature and claims. Revocation is checked on top of that, by TokenVerifier::verify: a token whose jti is denylisted, whose app’s revocation epoch post-dates it, or whose browser session is revoked is refused even though its signature is good. Three claims are there for revocation’s sake, one per way to revoke: the jti names one token, the sub and iat place it before or after its app was revoked, and the sid names the browser it was earned in.

    /// The SMART patient context, when the approval named one.

mint_access_token

The jti and the times are the mint’s own, never the caller’s, so no mint site can forget them or reuse an id. The server’s own minter, AccessTokenMinter::mint, sets the issuer and audience to the server’s origin.

Mint a signed access token using signing_key and the supplied claim inputs.

The jti and the times are the mint’s own, never the caller’s, so no mint site can forget them or reuse an id: a fresh random jti, iat from the mint’s clock, and exp the caller’s ttl after it.

Errors

Returns AccessTokenMintError::SigningKeyUnreadable if signing_key’s material cannot be turned into an EncodingKey, or AccessTokenMintError::JwsEncodeFailed if encoding the JWS fails.

#![allow(unused)]
fn main() {
pub fn mint_access_token(
    signing_key: &SigningKey,
    args: &NewAccessTokenArgs<'_>,
) -> Result<String, AccessTokenMintError> {
    let now = Utc::now();
    let claims = AccessTokenClaims {
        issuer: args.issuer.to_string(),
        subject: args.client_id.to_string(),
        // A fresh random `jti` per mint — generated here, not taken from
        // `NewAccessTokenArgs`, so *every* mint site (the OAuth token response, the
        // refresh/token-exchange path) gets a unique id
        // without having to remember to pass one.
        jti: uuid::Uuid::new_v4().to_string(),
        audience: args.audience.unwrap_or(args.issuer).to_string(),
        expires_at: now + args.ttl,
        issued_at: now,
        scope: args.scopes.join(" "),
        patient: args.patient.map(str::to_string),
        sid: args.sid.map(str::to_string),
    };
    let mut header = Header::new(Algorithm::RS256);
    header.kid = Some(signing_key.kid.clone());
    let enc =
        EncodingKey::try_from(signing_key).map_err(AccessTokenMintError::SigningKeyUnreadable)?;
    jsonwebtoken::encode(&header, &claims, &enc).map_err(AccessTokenMintError::JwsEncodeFailed)
}
}

Any minted token verifies against its key, issuer and audience (the issuer when none is named), and carries back exactly the claims it was minted with, living exactly its TTL from about now.

#![allow(unused)]
fn main() {
fn mint_and_verify_round_trip(
    client_id in "[a-zA-Z0-9_-]{1,32}",
    scopes in prop::collection::vec("[a-z][a-z0-9_]{0,15}", 0..5),
    ttl_seconds in 1i64..=3600,
    origin in "https://[a-z]{3,16}\\.[a-z]{2,8}",
    audience_suffix in prop::option::of("/[a-z]{2,16}"),
    patient in prop::option::of("[a-zA-Z0-9-]{1,32}"),
    sid in prop::option::of("[a-zA-Z0-9-]{1,36}"),
) {
    let key = shared_key();
    let audience: Option<String> = audience_suffix.map(|s| format!("{origin}{s}"));
    let expected_aud = audience.clone().unwrap_or_else(|| origin.clone());

    let before = Utc::now();
    let token = mint_access_token(
        key,
        &NewAccessTokenArgs {
            client_id: &client_id,
            scopes: &scopes,
            ttl: Duration::seconds(ttl_seconds),
            issuer: &origin,
            audience: audience.as_deref(),
            patient: patient.as_deref(),
            sid: sid.as_deref(),
        },
    ).expect("mint");

    let verified_claims = verify_access_token(
        &token,
        std::slice::from_ref(key),
        &AccessTokenVerifyOptions {
            expected_issuer: &origin,
            accepted_audiences: std::slice::from_ref(&expected_aud),
        },
    ).expect("verify");

    // Compare the whole struct so a Debug diff names every wrong field at once.
    let expected = VerifiedClaims {
        issuer: origin.clone(),
        subject: client_id.clone(),
        audience: vec![expected_aud],
        scope: Some(scopes.join(" ")),
        patient: patient.clone(),
        sid: sid.clone(),
        // `jti` is a fresh random id we can't predict, so mirror what
        // was minted; asserted non-empty separately below. Cloned (not
        // spread) because `Option<String>` isn't `Copy` — a bare
        // `..verified_claims` would partially move it and break the
        // `&verified_claims` comparison that follows.
        jti: verified_claims.jti.clone(),
        // Spread verified_claims for timestamps through —
        // they come from `Utc::now()` so we can't predict them
        ..verified_claims
    };
    prop_assert_eq!(&verified_claims, &expected);
    // Every mint stamps a non-empty `jti` (uniqueness is covered by
    // `each_mint_carries_a_unique_jti`).
    prop_assert!(verified_claims.jti.as_deref().is_some_and(|jti| !jti.is_empty()));

    let iat = verified_claims.issued_at.expect("iat present");
    let exp = verified_claims.expires_at.expect("exp present");
    prop_assert_eq!(exp - iat, Duration::seconds(ttl_seconds));
    // JWT timestamps are second-precision; allow a small slack window
    // around the wall-clock `before`/`now` envelope.
    prop_assert!((iat - before).num_seconds().abs() <= 2);
}
}

fn main() {
fn each_mint_carries_a_unique_jti(
    client_id in "[a-zA-Z0-9_-]{1,32}",
    origin in "https://[a-z]{3,16}\\.[a-z]{2,8}",
    mints in 2usize..=16,
) {
    let key = shared_key();
    let mut seen = std::collections::HashSet::new();
    for _ in 0..mints {
        let token = mint_access_token(key, &owner_args(&client_id, &origin)).expect("mint");
        let claims = verify_access_token(
            &token,
            std::slice::from_ref(key),
            &AccessTokenVerifyOptions {
                expected_issuer: &origin,
                accepted_audiences: std::slice::from_ref(&origin),

        .expect("verify");

        prop_assert!(!jti.is_empty(), "jti must be non-empty");

verify_access_token

Verify a JWT against possible_signing_keys, returning the decoded claims on success.

If the header carries a kid that matches any of the supplied keys, only those keys are tried; otherwise every key is attempted (allowing for rotation overlap).

Errors

Returns AccessTokenVerifyError::NoSigningKeysConfigured if possible_signing_keys is empty, AccessTokenVerifyError::SigningKeyUnreadable if a candidate key’s material cannot be turned into a DecodingKey, or AccessTokenVerifyError::TokenRejected if the token is empty, its header cannot be decoded, or no candidate key validates it.

#![allow(unused)]
fn main() {
pub fn verify_access_token(
    token: &str,
    possible_signing_keys: &[SigningKey],
    opts: &AccessTokenVerifyOptions<'_>,
) -> Result<VerifiedClaims, AccessTokenVerifyError> {
    let token = token.trim();
    if token.is_empty() {
        return Err(AccessTokenVerifyError::TokenRejected);
    }
    if possible_signing_keys.is_empty() {
        return Err(AccessTokenVerifyError::NoSigningKeysConfigured);
    }
    let header =
        jsonwebtoken::decode_header(token).map_err(|_| AccessTokenVerifyError::TokenRejected)?;

    let kid = header.kid.as_deref();
    let mut kid_matched = possible_signing_keys
        .iter()
        .filter(move |k| kid.is_some_and(|target| k.kid == target))
        .peekable();
    let mut candidates: Box<dyn Iterator<Item = &SigningKey> + '_> = if kid_matched.peek().is_some()
    {
        Box::new(kid_matched)
    } else {
        Box::new(possible_signing_keys.iter())
    };

    let mut validation = Validation::new(Algorithm::RS256);
    validation.set_issuer(&[opts.expected_issuer]);
    let audiences: Vec<&str> = opts.accepted_audiences.iter().map(String::as_str).collect();
    validation.set_audience(&audiences);
    validation.validate_exp = true;

    let try_verifying_with =
        |key: &SigningKey| -> Result<Option<VerifiedClaims>, AccessTokenVerifyError> {
            let dec =
                DecodingKey::try_from(key).map_err(AccessTokenVerifyError::SigningKeyUnreadable)?;
            Ok(
                jsonwebtoken::decode::<VerifiedClaims>(token, &dec, &validation)
                    .ok()
                    .map(|d| d.claims),
            )
        };

    candidates
        .find_map(|key| try_verifying_with(key).transpose())
        .unwrap_or(Err(AccessTokenVerifyError::TokenRejected))
}
}

AccessTokenVerifyError

The answers split by whose fault they are. A bad token and a revoked one are the caller’s, a 401, kept distinct so the logs can tell them apart. Everything else is the server’s, a 500, and a store that can’t say whether a token is revoked refuses it. verify_access_token itself answers only TokenRejected, NoSigningKeysConfigured and SigningKeyUnreadable; the rest come from the revocation checks in TokenVerifier.

Failures while verifying an access token.

verify_access_token itself answers only TokenRejected, NoSigningKeysConfigured and SigningKeyUnreadable. The rest come from the TokenVerifier capability, which runs it with the stored keys: KeyStoreUnavailable when it can’t read those keys, and Revoked, RevocationStoreUnavailable and BrowserSessionStoreUnavailable from its revocation checks.

#![allow(unused)]
fn main() {
pub enum AccessTokenVerifyError {
    /// Token did not pass cryptographic or claim validation; surface as 401.
    TokenRejected,
    /// No signing keys are configured — operator misconfiguration, surface as 500.
    NoSigningKeysConfigured,
    /// The signing-key store could not be read (e.g. the database query
    /// failed) — distinct from a key whose material is corrupt. Surface as 500.
    /// Wraps the domain [`AuthorizationServerError`]
    /// the store surfaced, so no database error type appears here.
    KeyStoreUnavailable(#[source] AuthorizationServerError),
    /// A configured signing key's material could not be turned into a
    /// `DecodingKey`.
    SigningKeyUnreadable(#[source] KeyMaterialError),
    /// The token verified cryptographically but has since been revoked — its
    /// `jti` is on the denylist, the subject's revocation epoch post-dates
    /// the token's `iat`, or the browser session its `sid` names is revoked. Surface as 401. Distinct from [`Self::TokenRejected`]
    /// so the caller and the logs can tell a revoked token from a bad one.
    Revoked,
    /// The revocation store could not be read (e.g. the database query failed)
    /// while checking whether a token was revoked. An operator problem, and we
    /// **fail closed** — surface as 500 rather than admit a possibly-revoked
    /// token — matching how [`Self::KeyStoreUnavailable`] is treated.
    RevocationStoreUnavailable(String),
    /// The browser session a token's `sid` names could not be read while
    /// checking whether it was revoked. Fails closed like
    /// [`Self::RevocationStoreUnavailable`].
    BrowserSessionStoreUnavailable(#[source] AuthorizationServerError),
}
}
