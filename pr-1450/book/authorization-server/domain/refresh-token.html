Refresh Token

Covers authorization-server-rust/src/domain/refresh_token.rs

An access token lasts minutes. An app the Owner allowed offline_access also gets a refresh token, which it trades at /oauth/token for a new access token, and a new refresh token, without asking anyone again. The first refresh token comes from redeeming an authorization code or from a device’s successful poll; every later one replaces the one before it.

That chain is a refresh family: every refresh token descended from one redemption. The family holds what they all share (the app, the scopes, the patient, the browser session, the deadline), and each token in it is one link. Only the newest link works. Presenting an older one kills the whole family, because a link presented twice means either a copy is loose or the app is broken, and either way the chain can’t be trusted. The app then has to run the authorization flow again.

A family is never deleted when it ends. Ending it moves its deadline to now and spends its live link, so the chain stays readable after the fact, and a replayed link still finds its dead family rather than reading as unknown. The retention sweep removes it later.

Before a presented link is spent, it is refused outright if its family belongs to another app, has passed its deadline (which covers a family already ended), was minted under a revoked browser session, or was begun before the app’s tokens were revoked (ValidatedRefreshToken::validate).

domain::refresh_token

RefreshTokenFamily

One authorization’s refresh-token lineage (RFC 6749 §6). The family owns every fact shared by all the tokens rotated under it — client, scopes, patient context, and the absolute deadline — so those are stated exactly once. Tokens (RefreshToken) reference it by family_id.

#![allow(unused)]
fn main() {
pub struct RefreshTokenFamily {
    /// Primary key — lineage id shared by every token descended from one
    /// authorization.
    pub family_id: String,
    /// Client the family was issued to; only it may refresh. A refresh token
    /// presented by any other client reads exactly like an unknown one.
    pub client_id: String,
    /// Scopes carried forward to every access token minted from this family,
    /// copied from the redemption that started it.
    pub scopes: Vec<String>,
    /// SMART-on-FHIR patient context recorded at authorization, if any.
    pub patient: Option<String>,
    /// When the family was created: the redemption or device poll that
    /// started it. Revoking the client refuses every family issued before
    /// that moment.
    pub issued_at: DateTime<Utc>,
    /// Absolute deadline for the whole family — rotation never extends it;
    /// past this the client must re-run the authorization flow. Ending the
    /// family (a replay, a revocation) moves it to the moment it ended,
    /// rather than deleting the row; the retention sweep removes it later.
    pub expires_at: DateTime<Utc>,
    /// SHA-256 base64url hash of the authorization `code` that minted this
    /// family, or `None` for grants with no authorization code (the
    /// device-code flow). On a detected code replay the family is revoked via
    /// this hash (RFC 6749 §4.1.2 / OAuth 2.1 §4.1.2.1). The plaintext code is
    /// never stored.
    pub authorization_code_hash: Option<String>,
    /// The [`Grant`](crate::domain::grant::Grant) that authorized this family,
    /// for **both** flows, written at family creation. Each rotation of a
    /// family a device grant earned stamps that grant's `last_used_at`.
    /// `None` when no matching grant was found at exchange time (e.g. a grant
    /// revoked between approval and the token poll). No FK: families outlive
    /// grants by design (expired in place, never deleted).
    pub grant_id: Option<String>,
    /// The browser session the family was minted under: for the code flow,
    /// that of the browser that made the request, which every code-flow
    /// family has; `None` for the device-code flow, which has none. Refresh
    /// is refused once that session is revoked. No FK: the retention sweep
    /// prunes an ended session only once no live family names it.
    pub sid: Option<String>,
}
}

RefreshToken

One rotation of a refresh token. Presenting the plaintext at /token with grant_type=refresh_token mints a fresh access token plus this token’s successor; the presented token is marked consumed. Replaying a consumed token is treated as theft and revokes the whole RefreshTokenFamily (OAuth 2.1 rotation semantics).

#![allow(unused)]
fn main() {
pub struct RefreshToken {

    /// plaintext is returned to the client once and never stored.
    pub token_hash: String,
    /// The [`RefreshTokenFamily`] this token belongs to.
    pub family_id: String,
    /// When this token was minted.
    pub issued_at: DateTime<Utc>,
    /// Set when this token is redeemed. `None` means this is the family's
    /// single live token.
    pub consumed_at: Option<DateTime<Utc>>,
}
}

RefreshTokenConsumeOutcome

Outcome of attempting to consume a refresh token — the primitive shape the GrantStore port returns, with the theft-vs-miss decision left to the caller.

#[must_use]: ignoring a Replayed outcome would skip the family revocation that reuse detection depends on, so the result must always be inspected.

#![allow(unused)]
fn main() {
pub enum RefreshTokenConsumeOutcome {
    /// The token was live and is now consumed. The caller can proceed with
    /// issuing new credentials and a new refresh token.
    Consumed,
    /// The token was already consumed — this is a replay, and the caller must
    /// reject the request and revoke the whole family.
    Replayed,
    /// No such token exists. The caller should treat this as a failed decode
    /// rather than a replay, so no need to revoke the family.
    NotFound,
}
}

consume_refresh_token

The test plants a family with one live link through the in-memory test fake (fixture).

Consume a live refresh token in the caller’s write scope, reporting which of the three RefreshTokenConsumeOutcome states the presented token was in. The guarded stamp and the existence probe run under the scope’s write lock, so of two concurrent redeemers of the same token exactly one stamps the live row (Consumed), and the other sees the row still present but no longer live (Replayed); an unknown hash is NotFound.

Errors

AuthorizationServerError::Infrastructure if the stamp or the existence probe fails.

#![allow(unused)]
fn main() {
pub(crate) fn consume_refresh_token(
    tx: &mut impl RefreshTokensTx,
    token_hash: &str,
    now: DateTime<Utc>,
) -> Result<RefreshTokenConsumeOutcome, AuthorizationServerError> {
    if tx.stamp_refresh_token_consumed_if_live(token_hash, now)? {
        Ok(RefreshTokenConsumeOutcome::Consumed)
    } else if tx.has_refresh_token(token_hash)? {
        Ok(RefreshTokenConsumeOutcome::Replayed)
    } else {
        Ok(RefreshTokenConsumeOutcome::NotFound)
    }
}
}

fn main() {
fn consume_reports_consumed_then_replayed_then_not_found() {
    let store = FakeGrantStore::default();
    live_token(&store, "live");
    let now = Utc::now();

    assert_eq!(
        consume_refresh_token(&mut store.tx(), "live", now).unwrap(),
        RefreshTokenConsumeOutcome::Consumed,
    );
    assert_eq!(
        consume_refresh_token(&mut store.tx(), "live", now).unwrap(),
        RefreshTokenConsumeOutcome::Replayed,
    );
    assert_eq!(
        consume_refresh_token(&mut store.tx(), "never-issued", now).unwrap(),
        RefreshTokenConsumeOutcome::NotFound,
    );
}
}
