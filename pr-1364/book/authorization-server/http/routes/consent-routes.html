A request that needs a decision is a consent prompt, and these routes are where it is read and decided. There are two surfaces. The code-flow prompt is an app’s code request, keyed by the request’s id, which the consent card shows. The device page’s prompt is keyed by the short user code the device page asks for: a device’s request through the device flow, or a browser asking to be paired (the polled requests).

Both surfaces live under /authorization, behind the session gate, and no answer is cached. Each handler acquires its capability through Scoped<…>: reading a prompt takes wildflower/AuthorizationRequest.r, deciding one takes wildflower/AuthorizationRequest.u, and a token without the scope gets a 403 naming it. The Owner holds both. A paired browser holds only what its pairing granted, so it may be able to read a prompt it can’t decide.

The rules of a decision (what an approval may grant, the acknowledgement, the patient, the race with another surface) belong to the capability: OAuth Consents for the code flow and Device Consents for the device page. The routes read the body, pass the server’s clock, and put the outcome on the wire, as a ConsentResult. The Consent Card, Approval Scopes and Device Code integration tests hold them end to end.

router

Asking the Owner raises a request for the Owner’s attention, so that route alone is wrapped in the deferred start limit the caller passes in.

The /oauth-consents route table. defer_start_limit wraps the ask-owner route, which raises a request for the Owner and so spends from the authorization start limit (see defer_authorization_start_limit).

#![allow(unused)]
fn main() {
pub fn router(
    defer_start_limit: impl Fn(
        MethodRouter<Arc<AuthorizationServerState>>,
    ) -> MethodRouter<Arc<AuthorizationServerState>>,
) -> Router<Arc<AuthorizationServerState>> {
    Router::new()
        .route("/oauth-consents/{id}", get::route())
        .route("/oauth-consents/{id}/approve", approve::route())
        .route("/oauth-consents/{id}/deny", deny::route())
        .route(
            "/oauth-consents/{id}/ask-owner",
            defer_start_limit(ask_owner::route()),
        )
}
}

The capability resolves the request against the app’s registration as it stands now, and answers 404 when the id names no live code-flow prompt: unknown, decided, expired, still waiting on its own browser’s limited page, or for an app disabled since.

#![allow(unused)]
fn main() {
async fn handle_get_oauth_consent(
    consents: Scoped<LiveConsentReader>,
    Path(id): Path<String>,
) -> Result<Json<OAuthConsent>, AuthorizationServerError> {
    let OAuthConsentView {
        pending_request,
        client_name,
        presented_client_change,
        missing_approval_scopes,
    } = consents.oauth_consent(&id, Utc::now())?;
    Ok(Json(OAuthConsent {
        id: id.clone(),
        patient: pending_request
            .state
            .approval()
            .and_then(|approval| approval.patient.clone()),
        client_id: pending_request.client_id,
        client_name,
        scopes: pending_request.requested_scopes,
        redirect_uri: pending_request.redirect_uri,
        pre_approved_scopes: pending_request.pre_approved_scopes,
        registration: presented_client_change.into(),
        missing_approval_scopes,
    }))
}
}

Wire shape of OAuthConsent::registration — the PresentedClientChange, status-tagged.

{"status":"registered"} for a request that matches the registration, {"status":"new"} for a client this authorization server has never seen, and {"status":"changed","redirectUriIsNew":…,"newScopes":[…]} when a known client steps outside its registration.

pub(crate) enum ClientRegistrationBody {
    /// The redirect is registered and every scope is covered: nothing new
    /// for the Owner to acknowledge.
    Registered,
    /// The Owner has never approved this app; nothing about it is stored
    /// until they do.
    New,
    /// The app is known, but the request steps outside its registration: a

        /// The requested scopes the registration does not cover, in request

    },
}

fn main() {
fn from(registration: PresentedClientChange) -> Self {
    match registration {
        PresentedClientChange::NoChange => ClientRegistrationBody::Registered,
        PresentedClientChange::WouldCreate => ClientRegistrationBody::New,
        PresentedClientChange::WouldWiden {
            redirect_uri_is_new,
            unregistered_requested_scopes: new_scopes,
        } => ClientRegistrationBody::Changed {
            redirect_uri_is_new,
            new_scopes,
        },
    }
}
}

handle_approve_oauth_consent

POST /authorization/oauth-consents/{id}/approve — the Owner approves a consent prompt, granting a (narrowed) scope set and minting the authorization code the polling endpoint hands back to the client. Gated by LiveConsentDecider (scope wildflower/AuthorizationRequest.u), which also carries the approver’s own scopes: an approval delegating a resource scope beyond them is rejected with a 403. Approving a prompt whose client, redirect, or scopes are outside the current registration without acknowledged_registration_change is rejected with a 409 and writes nothing, as is an approval naming a patient other than the one the request’s SMART launch binds. The write scope lives in the consent capability’s approve_oauth_consent.

The answers:

  • 200, "status":"approved": the code is issued; redirect is the app’s callback carrying it and the app’s state, for the card to leave for.
  • 200, "status":"denied": nothing was granted, the requesting browser’s session has ended, or the app was disabled since; the request is denied and redirect carries access_denied.
  • 403: the approver lacks an approval scope, or a ticked resource scope is beyond their own grant. Nothing is written.
  • 409: the registration change wasn’t acknowledged, or the body names a patient other than the one the launch bound. Nothing is written.
  • 404: no live code-flow prompt has this id.
#![allow(unused)]
fn main() {
async fn handle_approve_oauth_consent(
    consents: Scoped<LiveConsentDecider>,
    Path(id): Path<String>,
    Json(body): Json<ApproveOAuthConsentBody>,
) -> Result<Json<ConsentResult>, AuthorizationServerError> {
    let outcome = consents.approve_oauth_consent(
        &id,
        ApproveOAuthConsentInput {
            owner_approved_scopes: body.approved_scopes,
            patient: body.patient,
            acknowledged_registration_change: body.acknowledged_registration_change,
        },
        generate_authorization_code,
        Utc::now(),
    )?;
    Ok(Json(outcome.into()))
}
}

http::routes::oauth_consents::ask_owner

handle_ask_owner

A browser that can read a prompt but not approve it hands it to the Owner. The capability asks the start limit the layer deferred onto the request, and only when it is about to raise.

POST /authorization/oauth-consents/{id}/ask-owner — a browser that can read a consent prompt but not approve it hands it to the server’s Owner (scope wildflower/AuthorizationRequest.r, as reading it takes): the request no longer counts as decidable in the browser that made it, so the host notifies the Owner. Decides nothing. Raising a request spends from the authorization start limit, as starting one the Owner is asked about does: 429 Too Many Requests when refused, the request left as it was. Raising one already raised spends nothing. 204 No Content, or 404 once the request is no longer pending.

#![allow(unused)]
fn main() {
async fn handle_ask_owner(
    consents: Scoped<LiveConsentRaiser>,
    Extension(deferred_start_limit): Extension<DeferredStartLimit>,
    Path(id): Path<String>,
) -> Result<Response, AuthorizationServerError> {
    Ok(
        match consents.raise_for_owner(&id, || deferred_start_limit.admits(), Utc::now())? {
            OwnerRaising::Raised | OwnerRaising::AlreadyRaised => {
                StatusCode::NO_CONTENT.into_response()
            }
            OwnerRaising::StartLimited => start_limited_response(),
        },
    )
}
}

http::routes::devices::get

handle_get_device_consent

The device page loads the prompt for the code the approver typed. A code-flow request never reaches the match: the reader refuses one as not found.

GET /authorization/devices/{userCode} — load a pending device-code consent prompt for the launcher to render (scope wildflower/AuthorizationRequest.r).

#![allow(unused)]
fn main() {
async fn handle_get_device_consent(
    consents: Scoped<LiveConsentReader>,
    Path(user_code): Path<String>,
) -> Result<Json<DeviceConsent>, AuthorizationServerError> {
    let DeviceConsentView {
        request,
        client_name,
        starting_scopes,
        approvable_scopes,
        missing_approval_scopes,
    } = consents.device_consent(&user_code, Utc::now())?;
    let (kind, device_name) = match &request {
        PolledRequest::Pairing(pairing_request) => (
            DeviceConsentKind::Browser,
            Some(pairing_request.browser_name.clone()),
        ),
        PolledRequest::Device(device_request) => (
            DeviceConsentKind::Device,
            device_request.device_name.clone(),
        ),
    };
    Ok(Json(DeviceConsent {
        kind,
        user_code,
        client_id: request.client_id().to_owned(),
        client_name,
        device_name,
        starting_scopes,
        allowed_scopes: approvable_scopes,
        missing_approval_scopes,
    }))
}
}
