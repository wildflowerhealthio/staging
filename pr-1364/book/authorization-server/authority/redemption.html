Redemption

Covers authorization-server-rust/src/domain/authority/redemption.rs

An app’s back end comes to /oauth/token holding something it was given earlier: an authorization code, a device code, or a refresh token. It has already proved who it is with an authenticated client. Before an access token is minted for it, the thing it holds is redeemed into a proof, one per grant type. Each proof has one constructor, and that constructor is the whole redemption rule for its grant type: the single-use claim, the bindings to the app and redirect, the expiry, the PKCE check.

A proof’s scopes are copied from the record it redeemed, never from the request. The code carries the scopes its approval recorded; the device request carries the scopes the Owner granted; the refresh family carries the scopes it was started with. So a token can hold only what the consent behind it recorded.

Some refusals come after a write: a code is spent before its bindings are checked, a pending device poll is stamped before it is answered. Those refusals are the inner Err of a nested result, so the token exchange’s scope commits what it wrote rather than rolling it back. Only a store failure is the outer Err, and the token-exchange errors are the inner one’s vocabulary.

redeem

The code is taken out of the store in one step (AuthorizationCodesTx::redeem_authorization_code), so of two redemptions racing for one code, only one gets it back. A code that comes back missing may be a replay, so every refresh family started from it is expired (RefreshTokensTx::expire_refresh_token_families_for_authorization_code) before the refusal. A standing grant revoked between approval and redemption just leaves the proof’s grant_id empty.

Check the presented request is well formed, then atomically read-and-consume the code and verify every binding. A code is spent the moment it is presented, and only then checked, so of two redemptions racing for one code only one gets it, and a code that fails a binding can’t be retried into a token. A malformed request is refused before the code is touched. A code that is gone (redeemed or never issued) is a possible replay: any refresh family minted from it is revoked before the refusal (RFC 6749 §4.1.2). The binding failures all collapse to invalid_grant on the wire (the reason is logged), so a response never reveals which check failed.

The refusals, as the inner Err: TokenExchangeError::InvalidCodeVerifier (RFC 7636 §4.1 length) or TokenExchangeError::InvalidRedirectUri for a malformed request, and TokenExchangeError::InvalidGrant with the specific reason.

#![allow(unused)]
fn main() {
pub(crate) fn redeem(
    tx: &mut (impl AuthorizationCodesTx + RefreshTokensTx + GrantsTx),
    authenticated_client: &AuthenticatedClient,
    presented: &PresentedAuthorizationCode<'_>,
    now: DateTime<Utc>,
) -> Result<Result<Self, TokenExchangeError>, AuthorizationServerError> {
    if !is_valid_code_verifier_length(presented.code_verifier) {
        return Ok(Err(TokenExchangeError::InvalidCodeVerifier));
    }
    let Ok(redirect_uri) = Url::parse(presented.redirect_uri) else {
        return Ok(Err(TokenExchangeError::InvalidRedirectUri));
    };
    // A concurrent redemption of the same code can only succeed once, so
    // any racer past this point sees `None` (RFC 6749 §10.5).
    let Some(code) = tx.redeem_authorization_code(presented.code)? else {
        tx.expire_refresh_token_families_for_authorization_code(
            &token_storage_hash(presented.code),
            now,
        )?;
        return Ok(Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::CodeNotFoundOrRedeemed,
        )));
    };
    if let Err(reason) =
        check_code_bindings(&code, authenticated_client, &redirect_uri, presented, now)
    {
        return Ok(Err(TokenExchangeError::InvalidGrant(reason)));
    }
    // The standing grant behind this exchange, recorded on the family; a
    // grant revoked between approval and redemption just leaves it `None`.
    let grant_id = tx
        .grant_by_client_and_redirect(authenticated_client.client_id(), &redirect_uri)?
        .map(|grant| grant.id);
    Ok(Ok(RedeemedAuthorizationCode {
        token_scopes: token_scope_spellings(&code.granted_scopes),
        code,
        grant_id,
    }))
}
}

check_code_bindings

Each failure is its own invalid_grant reason, for the log; the wire answer is invalid_grant whichever failed. The code is already spent, so none of them can be retried into a token.

Why the consumed code may not be redeemed by authenticated_client with redirect_uri and the presented verifier at now, if anything: it must be the client’s, for that redirect, unexpired, and its PKCE challenge must match the verifier. Each failure is its own InvalidGrantReason, for the log; the code is already spent, so none can be retried into a token.

#![allow(unused)]
fn main() {
fn check_code_bindings(
    code: &AuthorizationCode,
    authenticated_client: &AuthenticatedClient,
    redirect_uri: &Url,
    presented: &PresentedAuthorizationCode<'_>,
    now: DateTime<Utc>,
) -> Result<(), InvalidGrantReason> {
    if code.client_id != authenticated_client.client_id() {
        return Err(InvalidGrantReason::CodeClientMismatch {
            code_client_id: code.client_id.clone(),
            presented_client_id: authenticated_client.client_id().to_owned(),
        });
    }
    if code.redirect_uri != *redirect_uri {
        return Err(InvalidGrantReason::CodeRedirectMismatch {
            code_redirect_uri: code.redirect_uri.to_string(),
            presented_redirect_uri: redirect_uri.to_string(),
        });
    }
    if code.expires_at < now {
        return Err(InvalidGrantReason::CodeExpired {
            expires_at: code.expires_at,
        });
    }
    let computed = compute_code_challenge(presented.code_verifier);
    if !bool::from(code.code_challenge.as_bytes().ct_eq(computed.as_bytes())) {
        return Err(InvalidGrantReason::PkceMismatch {
            client_id: authenticated_client.client_id().to_owned(),
        });
    }
    Ok(())
}
}

consume

A device request is claimed once. The claim is the request’s own claim transition, written with the guarded replace under the scope’s write lock, so of two polls racing for one approval, one wins. The standing grant is found by the device’s grant name.

Resolve the device request for device_code, require it to be this client’s, unexpired, and approved (stamping the poll and throttling a still-pending one per §3.5), then claim it, single use, under the scope’s write lock, so two concurrent polls can’t both mint. Once claimed, the standing device grant is looked up by the client and the device’s grant name (device_grant_name) and recorded on the proof.

Each poll is answered by the request’s state:

  • unknown, another client’s, or not a device request: invalid_grant, the three alike;
  • past its expiry, whatever its status: expired_token;
  • pending, polled again within DEVICE_CODE_POLL_INTERVAL of the last poll: slow_down, and the poll is not stamped;
  • pending otherwise: authorization_pending, and the poll is stamped;
  • denied: access_denied;
  • already claimed: expired_token, since the device code has done its work;
  • approved: claimed, and the proof returned; a poll that loses the claim to a concurrent one is invalid_grant.

The refusals, as the inner Err: the §3.5 poll outcomes (ExpiredToken, AuthorizationPending, AccessDenied, SlowDown), with an already-claimed request answering ExpiredToken; TokenExchangeError::InvalidGrant for an unknown request, or one whose guarded claim loses a race to a concurrent poll.

Errors

AuthorizationServerError::Infrastructure on a store failure.

#![allow(unused)]
fn main() {
pub(crate) fn consume(
    tx: &mut (impl AuthorizationRequestsTx + GrantsTx),
    authenticated_client: &AuthenticatedClient,
    device_code: &str,
    now: DateTime<Utc>,
) -> Result<Result<Self, TokenExchangeError>, AuthorizationServerError> {
    // One outcome collapses "no such device_code", "wrong client", and
    // "not a device request".
    let Some(request) = tx
        .device_request_by_id(device_code)?
        .filter(|request| request.client_id == authenticated_client.client_id())
    else {
        return Ok(Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::DeviceRequestNotFound {
                presented_client_id: authenticated_client.client_id().to_owned(),
            },
        )));
    };
    if request.is_expired_at(now) {
        return Ok(Err(TokenExchangeError::ExpiredToken));
    }
    let approval = match &request.state {
        PolledState::Pending => {
            if request.is_polled_too_soon_at(now) {
                return Ok(Err(TokenExchangeError::SlowDown));
            }
            if let Ok(stamped) = request.stamp_poll(now) {
                tx.replace_device_request(&request, &stamped)?;
            }
            return Ok(Err(TokenExchangeError::AuthorizationPending));
        }
        PolledState::Denied => return Ok(Err(TokenExchangeError::AccessDenied)),
        // A claimed request already minted its token: as RFC 8628 §3.5
        // has it, the device code has expired.
        PolledState::Claimed(_) => return Ok(Err(TokenExchangeError::ExpiredToken)),
        PolledState::Approved(approval) => approval.clone(),
    };
    let claimed = request.claim(now).map_err(|_| {
        AuthorizationServerError::infrastructure(
            "claiming a device request",
            "an approved, unexpired request is not claimable",
        )
    })?;
    if !tx.replace_device_request(&request, &claimed)? {
        return Ok(Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::DeviceCodeAlreadyRedeemed {
                client_id: request.client_id.clone(),
            },
        )));
    }
    let grant_name =
        device_grant_name(request.device_name.as_deref(), authenticated_client.name());
    let grant_id = tx
        .device_grant_by_client_and_device_name(&request.client_id, grant_name)?
        .map(|grant| grant.id);
    Ok(Ok(ConsumedDeviceRequest {
        token_scopes: token_scope_spellings(&approval.granted_scopes),
        client_id: request.client_id.clone(),
        approval,
        grant_id,
    }))
}
}

validate

The epoch is the app’s revocation epoch: bumping it revokes every token the app held at that instant, so a family begun before it is refused like an access token issued before it.

Resolve the presented token’s family and require it to be this client’s, unexpired, not minted under a revoked browser session, and begun no earlier than its client’s revocation epoch. A valid token presented by the wrong client is answered exactly like an unknown one so a stranger can’t probe validity, and is refused before any consume so it can’t burn the rightful client’s token. A family begun at the epoch itself still validates. Bumping a client’s revocation epoch revokes every token it held at that instant, so a family begun before it is refused like an access token issued before it. Runs in a read scope, outside the write lock (see the type’s doc).

Errors

TokenExchangeError::InvalidGrant with the specific reason; TokenExchangeError::Store on a store failure, the revocation store’s included, so an unreadable epoch never admits a family.

#![allow(unused)]
fn main() {
pub(crate) fn validate(
    tx: &mut (impl RefreshTokensTx + BrowserSessionsTx),
    revocation: &dyn RevocationCheck,
    authenticated_client: &AuthenticatedClient,
    presented_refresh_token: &str,
    now: DateTime<Utc>,
) -> Result<Self, TokenExchangeError> {
    let validated = Self::live_family(
        tx,
        authenticated_client,
        token_storage_hash(presented_refresh_token),
        now,
    )?;
    // Bumping a client's revocation epoch revokes every token it held at
    // that instant, refresh families included: a family begun before the
    // epoch is refused like an access token issued before it. The family
    // has no `jti` of its own, so only the epoch applies.
    let family_predates_client_epoch = revocation
        .is_revoked(
            None,
            Some(validated.family.issued_at),
            &validated.family.client_id,
        )
        .map_err(|error| {
            AuthorizationServerError::infrastructure(
                "refresh-token revocation epoch check failed",
                error,
            )
        })?;
    if family_predates_client_epoch {
        return Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::RefreshTokenClientRevoked {
                family_id: validated.family.family_id,
            },
        ));
    }
    Ok(validated)
}

live_family

The half both constructors run. A revoked family is one whose deadline was pulled back to the revocation instant, so the deadline check covers both. The browser session is checked with BrowserSessionsTx::is_browser_session_revoked.

The store-only half of validation: the family presented_hash belongs to, required to be authenticated_client’s, unexpired at now, and not minted under a revoked browser session. A revoked family is one whose deadline was pulled back to the revocation instant, so the deadline check covers both.

#![allow(unused)]
fn main() {
fn live_family(
    tx: &mut (impl RefreshTokensTx + BrowserSessionsTx),
    authenticated_client: &AuthenticatedClient,
    presented_hash: String,
    now: DateTime<Utc>,
) -> Result<Self, TokenExchangeError> {
    let Some((_, family)) = tx.refresh_token_with_family_by_hash(&presented_hash)? else {
        return Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::RefreshTokenNotFound,
        ));
    };
    if family.client_id != authenticated_client.client_id() {
        return Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::RefreshTokenClientMismatch {
                family_client_id: family.client_id,
                presented_client_id: authenticated_client.client_id().to_owned(),
            },
        ));
    }
    // Covers both natural deadline passage and prior revocation — revoking
    // pulls `expires_at` back to the revocation instant rather than
    // deleting rows, so the lineage stays auditable.
    if family.expires_at <= now {
        return Err(TokenExchangeError::InvalidGrant(
            InvalidGrantReason::RefreshTokenExpired,
        ));
    }
    // Revoking a browser session ends every family minted under it. A
    // family with no session (the device flow) has none to check.
    if let Some(sid) = family.sid.as_deref() {
        if tx.is_browser_session_revoked(sid)? {
            return Err(TokenExchangeError::InvalidGrant(
                InvalidGrantReason::RefreshTokenSessionRevoked {
                    family_id: family.family_id,
                },
            ));
        }
    }
    Ok(ValidatedRefreshToken {
        token_scopes: token_scope_spellings(&family.scopes),
        family,
        presented_hash,
    })
}
}
