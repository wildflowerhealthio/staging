Same-Device Sign-In Codes

Covers authorization-server-rust/src/domain/same_device_sign_in_codes.rs

Covers authorization-server-rust/src/domain/sign_in_redirect.rs

The Owner signs a browser in by asking the base, the Wildflower app on the device that runs the server. The base mints a same-device sign-in code in-process and opens GET /oauth/sign-in?code=…&next=… in a browser. Whoever presents the code there first, in time, starts a same-device browser session in that browser. Only the base can mint a code, and the base runs on the server’s own device, so redeeming one stands for “this browser is on the Owner’s device”. The same-device sign-in proof is that redemption; this page is the codes it redeems from, and where the browser may be sent once it is signed in.

A code is single-use, short-lived, and never stored in the clear. Each is 256 random bits, redeemable once, for a minute. The outstanding codes live only in the server’s memory and only as SHA-256 hashes: a restart drops them all, and reading the server’s memory yields none.

The set follows each code past its redemption, by the same hash: while the session it starts is being stored, for a minute at most, after which a sign-in that never finished is given up on, and then which session it started, until that session expires. The base holds each code it minted as a SameDeviceSignInCode: the code with the set of the run that minted it, and nothing of the run’s store, so it outlives that run. Through it the base withdraws the code once the view it was opened in closes: an unredeemed code is no longer redeemable, and a code withdrawn while its session is still being stored signs nobody in, the session never landing. Through it the same-device session ender finds the session to end once the server’s last launch view closes, and setup the session to exempt from the next run’s stale-session cutoff while a view is still open. A code forgets its session only once the ending has landed, so a failed ending can be tried again.

Where a sign-in may send the browser

A sign-in URL carries a next: where the browser goes once its session has started. A next is held to an allow-list, so a sign-in link can’t be turned into a redirect to anywhere. A next is allowed when it is

  • a path on this server: it starts with / but not //, and still names this server’s origin once resolved against it;
  • a URL under the hosted launcher or the Wildflower Authorization app;
  • a URL under the pages the host opens for this server, its own launcher and Authorization app: the page itself, whatever its query, or a URL within it as a folder.

Each is judged by the URL a browser would make of it, parsed as the WHATWG URL standard says, so spellings a browser reads as another host (/\evil.example, a tab inside //, user@host) resolve to that host here too, and are refused. The redirect is the parsed URL re-serialized, never the raw next. The sign-in checks next before it touches the code, so a refused next leaves the code redeemable.

A browser pairing’s next is held tighter: a paired browser is only ever sent on to this server’s own /oauth/authorize.

insert

Minting a code. The base’s minter, SameDeviceSignInCodeMinter, calls this with each code it generates.

Keep code redeemable until SAME_DEVICE_SIGN_IN_CODE_TTL past now. The codes already expired at now, the sign-ins given up on by now, and the sessions already expired at now, are dropped, so only live ones are kept.

#![allow(unused)]
fn main() {
pub(crate) fn insert(&self, code: &str, now: DateTime<Utc>) {
    let mut sign_in_by_code_hash = self.sign_in_by_code_hash.lock();
    sign_in_by_code_hash.retain(|_, sign_in| match sign_in {
        CodeSignIn::Outstanding { expires_at }
        | CodeSignIn::SigningIn { expires_at }
        | CodeSignIn::WithdrawnWhileSigningIn { expires_at }
        | CodeSignIn::SignedIn { expires_at, .. } => *expires_at > now,
    });
    sign_in_by_code_hash.insert(
        token_storage_hash(code),
        CodeSignIn::Outstanding {
            expires_at: now + SAME_DEVICE_SIGN_IN_CODE_TTL,
        },
    );
}
}

take

Redeeming a code.

Redeem presented: whether it was outstanding, and unexpired at now. Redeemed, its session is being stored until session_stored or session_not_stored says how that went, or, past SAME_DEVICE_SIGN_IN_CODE_TTL from now, the sign-in is given up on as one that never finished; an expired one is dropped. Either way it is no longer outstanding, so a code is redeemed at most once and an expired one is spent by the attempt. The presented code is hashed before the lookup, which compares hashes, never the code itself.

#![allow(unused)]
fn main() {
pub(crate) fn take(&self, presented: &str, now: DateTime<Utc>) -> bool {
    let mut sign_in_by_code_hash = self.sign_in_by_code_hash.lock();
    let code_hash = token_storage_hash(presented);
    match sign_in_by_code_hash.get(&code_hash) {
        Some(CodeSignIn::Outstanding { expires_at }) if *expires_at > now => {
            sign_in_by_code_hash.insert(
                code_hash,
                CodeSignIn::SigningIn {
                    expires_at: now + SAME_DEVICE_SIGN_IN_CODE_TTL,
                },
            );
            true
        }
        Some(CodeSignIn::Outstanding { .. }) => {
            sign_in_by_code_hash.remove(&code_hash);
            false
        }
        _ => false,
    }
}
}

session_stored

The sign-in calls this once the session it started is stored.

The session the redeemed code started has been stored: remember it, so the code finds its sid, and return true; or, when the code was withdrawn meanwhile, or its sign-in given up on, forget the code and return false, for the caller to roll the session back.

#![allow(unused)]
fn main() {
pub(crate) fn session_stored(&self, code: &str, session: &BrowserSession) -> bool {
    let mut sign_in_by_code_hash = self.sign_in_by_code_hash.lock();
    let code_hash = token_storage_hash(code);
    if !matches!(
        sign_in_by_code_hash.get(&code_hash),
        Some(CodeSignIn::SigningIn { .. })
    ) {
        sign_in_by_code_hash.remove(&code_hash);
        return false;
    }
    sign_in_by_code_hash.insert(
        code_hash,
        CodeSignIn::SignedIn {
            sid: session.sid.clone(),
            expires_at: session.expires_at,
        },
    );
    true
}
}

Withdraw code: an outstanding code is no longer redeemable, and one whose session is being stored signs nobody in. A code that signed a browser in keeps its session, for signed_in_sid to find.

#![allow(unused)]
fn main() {
pub(crate) fn withdraw(&self, code: &str) {
    let mut sign_in_by_code_hash = self.sign_in_by_code_hash.lock();
    let code_hash = token_storage_hash(code);
    match sign_in_by_code_hash.get(&code_hash) {
        Some(CodeSignIn::Outstanding { .. }) => {
            sign_in_by_code_hash.remove(&code_hash);
        }
        Some(CodeSignIn::SigningIn { expires_at }) => {
            let expires_at = *expires_at;
            sign_in_by_code_hash.insert(
                code_hash,
                CodeSignIn::WithdrawnWhileSigningIn { expires_at },
            );
        }
        Some(CodeSignIn::WithdrawnWhileSigningIn { .. } | CodeSignIn::SignedIn { .. })
        | None => {}
    }
}
}

fn main() {
fn is_under(url: &Url, page: &Url) -> bool {
    let folder = if page.path().ends_with('/') {
        page.path().to_owned()
    } else {
        format!("{}/", page.path())
    };
    url.origin() == page.origin()
        && url.username().is_empty()
        && url.password().is_none()
        && (url.path() == page.path() || url.path().starts_with(&folder))
}
