A client is an app that asks for access to the Owner’s FHIR server: a SMART app in a browser, a Pebble companion, the host app. It names itself with a client_id on every request. A client that can keep a secret is confidential and authenticates with its credentials; a client that can’t (a single-page app, a native app) is public.

Every client has a registration: the redirect URIs it may send a browser back to, the scopes it may ask for, and the grant types it may use at /oauth/token. Who defines the registration decides how a request is judged against it. A few clients belong to the server itself, and their registration is fixed: a request is held to it as it stands. Every other client is trusted on first use. An app the server has never seen isn’t turned away at /oauth/authorize. Its request goes to the Owner with a warning, and the Owner’s approval writes the registration, or widens it when a known app steps outside what it registered.

That warning is the presented client change: what approving the request would change in the app’s registration. Nothing, if the request stays inside it; create it, for an app the Owner has never approved; or widen it, by a new redirect, new scopes, or both. The change is derived from the current row on every read, never stored, so a consent prompt opened after the row moved shows the move. A request that would change the registration never skips the Owner, even when a standing grant would cover it.

Two clients the Owner can’t switch off at all, because they are how the Owner gets in: they are essential.

Client

A registered OAuth client — the identity and policy bundle that /authorize and /token look up by client_id. Diesel-mapped 1:1 to the clients table; the JSON list columns convert through the column newtypes in crate::db::clients and crate::db::shared at the bind/read boundary.

#![allow(unused)]
fn main() {
pub struct Client {
    /// Primary key — the app's public name for itself, sent on every request.
    pub client_id: String,
    /// Human-readable label: what the consent card calls the app.
    pub name: String,
    /// Whether the client can keep a secret (`Confidential`) or not (`Public`).
    pub kind: ClientKind,
    /// Allowlist of absolute redirect URIs; `/authorize` requires an exact
    /// match against this set.
    pub redirect_uris: Vec<Url>,
    /// Scopes the client is permitted to request, matched by coverage: a
    /// broad scope admits the narrower ones it covers. A request outside them
    /// is refused for a server-defined registration, and goes to the Owner as
    /// a registration change for one trusted on first use.
    pub allowed_scopes: Vec<String>,
    /// Grant types the client may use at `/token`; a grant outside this set is
    /// rejected with `unauthorized_client` (RFC 6749 §5.2).
    pub allowed_grant_types: Vec<AllowedGrantType>,
    /// argon2id PHC string of the client secret for `Confidential` clients;
    /// `None` for `Public`.
    pub secret_hash: Option<String>,
    /// When the client was registered.
    pub registered_at: DateTime<Utc>,
    /// Set when the Owner disabled the client: a disabled app gets nothing at
    /// `/authorize` or `/token`. `None` while it is enabled.
    pub disabled_at: Option<DateTime<Utc>>,
    /// Who defines the registration: the server, which seeds it and holds
    /// requests to it, or the Owner's approvals, which create and widen it.
    pub registration_source: RegistrationSource,
}
}

PresentedClientChange

What approving an authorization-code request would change in its client’s registration: the registration it presents (see PresentedClientRegistration) judged against the current clients row. The consent prompt renders it as the Owner-facing warning.

#![allow(unused)]
fn main() {
pub enum PresentedClientChange {
    /// The row exists, the `redirect_uri` is on its allowlist, and every
    /// requested scope is covered by `allowed_scopes`: approving changes
    /// nothing. The only change that may take the existing-grant fast path at
    /// `/authorize`.
    NoChange,
    /// No row exists for this `client_id`: approving would create one. Nothing
    /// is persisted for such a client until the Owner approves.
    WouldCreate,
    /// The row exists but the presented registration steps outside it, so
    /// approving would widen the row (for a client trusted on first use).
    WouldWiden {
        /// The presented `redirect_uri` is not on the allowlist.
        redirect_uri_is_new: bool,
        /// The requested scopes no `allowed_scopes` entry covers, in request
        /// order. Empty when only the redirect changed.
        unregistered_requested_scopes: Vec<String>,
    },
}
}

from_presented_registration

Judge presented_registration against its current client row.

@returns WouldCreate when no row exists, NoChange when the redirect is on the allowlist and every requested scope is covered, and WouldWiden otherwise — carrying which of the two stepped outside the registration.

Scope coverage is the same coverage-aware check the rest of the slice uses (wildflowerhealthio_scopes::allowed_scope_covers): a client allowed a broad scope also covers a narrower same-grammar request. An unparseable scope parses to an Unknown scope that only covers itself, so it is reported as new unless the registration lists it verbatim — deliberately, since the Owner should see an unrecognized scope string.

#![allow(unused)]
fn main() {
pub(crate) fn from_presented_registration(
    presented_registration: &PresentedClientRegistration<'_>,
) -> PresentedClientChange {
    let Some(existing_client) = presented_registration.maybe_existing_client else {
        return PresentedClientChange::WouldCreate;
    };
    let redirect_uri_is_new =
        !existing_client.allows_redirect_uri(presented_registration.redirect_uri);
    let unregistered_requested_scopes = uncovered_scopes(
        &existing_client.allowed_scopes,
        presented_registration.scopes,
    );
    if redirect_uri_is_new || !unregistered_requested_scopes.is_empty() {
        PresentedClientChange::WouldWiden {
            redirect_uri_is_new,
            unregistered_requested_scopes,
        }
    } else {
        PresentedClientChange::NoChange
    }
}
}

authorization-server-rust/src/domain/client/presented_change.rs lines 205–218 · authorization-server in the code index

The change is exactly one of the three, and each is decided by the two facts it reports: NoChange iff the redirect is allowlisted and nothing is uncovered, and a WouldWiden change never carries both “nothing new” flags (that would be NoChange). The reported unregistered_requested_scopes are always a subset of what was requested, in request order.

#![allow(unused)]
fn main() {
fn the_change_agrees_with_what_it_reports(
    registered in prop::collection::vec(arb_plain_scope(), 0..5),
    requested in prop::collection::vec(arb_plain_scope(), 0..5),
    allowlisted in any::<bool>(),
) {
    let mut app = client("app", &[]);
    app.allowed_scopes = registered;
    if !allowlisted {
        app.redirect_uris = Vec::new();
    }
    let change = PresentedClientChange::from_presented_registration(&PresentedClientRegistration {
        maybe_existing_client: Some(&app),
        redirect_uri: &redirect(),
        scopes: &requested,
    });
    let uncovered = uncovered_scopes(&app.allowed_scopes, &requested);
    match change {
        PresentedClientChange::WouldCreate => prop_assert!(false, "a known client never WouldCreate"),
        PresentedClientChange::NoChange => {
            prop_assert!(allowlisted);
            prop_assert!(uncovered.is_empty());
        }
        PresentedClientChange::WouldWiden { redirect_uri_is_new, unregistered_requested_scopes } => {
            prop_assert_eq!(redirect_uri_is_new, !allowlisted);
            prop_assert_eq!(&unregistered_requested_scopes, &uncovered);
            prop_assert!(redirect_uri_is_new || !unregistered_requested_scopes.is_empty());
            // A subset of the request, in request order.
            let mut remaining = requested.iter();
            for new_scope in &unregistered_requested_scopes {
                prop_assert!(remaining.any(|r| r == new_scope));
            }
        }
    }
}
}
