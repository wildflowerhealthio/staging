Token Revocation

Covers authorization-server-rust/tests/integration/token_revocation.rs

POST /oauth/revoke (RFC 7009) is how an app gives up a token it holds, say when its user signs out of it. The app authenticates as it does at /oauth/token: a public client by its client_id, a confidential one with its secret too. Then:

  • A refresh token ends its whole family, whichever generation is presented.
  • An access token is denylisted by its jti until it expires, if this server minted it for that client.
  • Anything else is answered alike and left alone: a token the server never issued, one already dead, another server’s, and another client’s. The answer is always 200 with an empty body, so an app learns nothing about a token that isn’t its own.

The server tells the token’s type from the token itself and never reads token_type_hint. The revoker is ClientTokenRevoker::revoke. The file’s last two tests hold refresh redemption to the client’s revocation epoch, which Revocation introduces: a family begun before its client’s epoch no longer refreshes.

This file’s own helpers are on the Test Fixtures page, with the shared ones.

an_app_revokes_its_own_refresh_token

An app revokes its own refresh token: the whole family ends, so neither that token nor its successor refreshes again.

#![allow(unused)]
fn main() {
async fn an_app_revokes_its_own_refresh_token() {
    let (g, _owner_token, db) = spin_up();
    seed_public_clients(&db);
    plant_refresh_token(
        &store_handle(&db),
        "app-refresh",
        APP_CLIENT_ID,
        Utc::now() + Duration::days(30),
    );
    let res = refresh(&g, APP_CLIENT_ID, "app-refresh").await;
    assert_eq!(res.status(), StatusCode::OK);
    let successor = body_json(res.into_body()).await["refresh_token"]
        .as_str()
        .expect("a successor")
        .to_owned();

    assert_revocation_answered(
        revoke(&g, APP_CLIENT_ID, &successor).await,
        "revoking the app's own refresh token",
    )
    .await;

    assert_refresh_revoked(refresh(&g, APP_CLIENT_ID, &successor).await).await;
}
}

an_app_revokes_its_own_access_token

An app revokes its own access token: its jti is denylisted, so the token no longer authenticates anywhere.

#![allow(unused)]
fn main() {
async fn an_app_revokes_its_own_access_token() {
    let (g, _owner_token, db) = spin_up();
    seed_public_clients(&db);
    let access_token = mint_client_token(&db, APP_CLIENT_ID, &["openid"]);
    let gate_status = |token: String| {
        let router = g.router.clone();
        async move {
            router
                .oneshot(owner_grants_probe(&token))
                .await
                .expect("oneshot")
                .status()
        }
    };
    assert_eq!(
        gate_status(access_token.clone()).await,
        StatusCode::FORBIDDEN,
        "live, though it reaches no /authorization scope"
    );

    assert_revocation_answered(
        revoke(&g, APP_CLIENT_ID, &access_token).await,
        "revoking the app's own access token",
    )
    .await;

    assert!(revocation_store_handle(&db)
        .is_revoked_by_jti(&jti_of(&access_token))
        .expect("query"));
    assert_eq!(
        gate_status(access_token).await,
        StatusCode::UNAUTHORIZED,
        "the revoked token no longer authenticates"
    );
}
}

another_client_s_tokens_are_answered_alike_and_left_alone

Another client’s tokens get the same 200 as the app’s own, and are left alone: the other client still refreshes, and its access token is not denylisted.

#![allow(unused)]
fn main() {
async fn another_client_s_tokens_are_answered_alike_and_left_alone() {
    let (g, _owner_token, db) = spin_up();
    seed_public_clients(&db);
    plant_refresh_token(
        &store_handle(&db),
        "other-refresh",
        OTHER_CLIENT_ID,
        Utc::now() + Duration::days(30),
    );
    let other_access_token = mint_client_token(&db, OTHER_CLIENT_ID, &["openid"]);

    assert_revocation_answered(
        revoke(&g, APP_CLIENT_ID, "other-refresh").await,
        "another client's refresh token",
    )
    .await;
    assert_revocation_answered(
        revoke(&g, APP_CLIENT_ID, &other_access_token).await,
        "another client's access token",
    )
    .await;

    assert_eq!(
        refresh(&g, OTHER_CLIENT_ID, "other-refresh").await.status(),
        StatusCode::OK,
        "the other client's family lives on"
    );
    assert!(!revocation_store_handle(&db)
        .is_revoked_by_jti(&jti_of(&other_access_token))
        .expect("query"));
}
}

a_confidential_client_revokes_with_its_secret

A confidential client authenticates with its secret, as at /oauth/token: a wrong Basic secret is 401 invalid_client with a Basic challenge; the right one revokes.

#![allow(unused)]
fn main() {
async fn a_confidential_client_revokes_with_its_secret() {
    let (g, _db) = spin_up_with_confidential_client();
    let res = post_form_with_authorization(
        &g.router,
        "/oauth/revoke",
        "token=conf-token".to_string(),
        &basic_authorization(CONFIDENTIAL_CLIENT_ID, "not-the-secret"),
    )
    .await;
    assert_eq!(res.status(), StatusCode::UNAUTHORIZED);
    assert_eq!(
        res.headers()
            .get("www-authenticate")
            .map(|v| v.to_str().unwrap()),
        Some(r#"Basic realm="wildflower-authorization""#)
    );
    assert_eq!(body_json(res.into_body()).await["error"], "invalid_client");

    let res = post_form_with_authorization(
        &g.router,
        "/oauth/revoke",
        "token=conf-token&token_type_hint=refresh_token".to_string(),
        &basic_authorization(CONFIDENTIAL_CLIENT_ID, CONFIDENTIAL_CLIENT_SECRET),
    )
    .await;
    assert_revocation_answered(res, "the confidential client's refresh token").await;
    let res = post_form_with_authorization(
        &g.router,
        "/oauth/token",
        "grant_type=refresh_token&refresh_token=conf-token".to_string(),
        &basic_authorization(CONFIDENTIAL_CLIENT_ID, CONFIDENTIAL_CLIENT_SECRET),
    )
    .await;
    assert_refresh_revoked(res).await;
}
}

bumping_the_client_s_epoch_stops_refresh

Bumping the client’s revocation epoch (here the Owner’s subject revoke) stops every refresh family it held: the next refresh is invalid_grant.

#![allow(unused)]
fn main() {
async fn bumping_the_client_s_epoch_stops_refresh() {
    let (g, owner_token, db) = spin_up();
    seed_public_clients(&db);
    plant_refresh_token(
        &store_handle(&db),
        "app-refresh",
        APP_CLIENT_ID,
        Utc::now() + Duration::days(30),
    );
    plant_refresh_token(
        &store_handle(&db),
        "other-refresh",
        OTHER_CLIENT_ID,
        Utc::now() + Duration::days(30),
    );

    let res = g
        .router
        .clone()
        .oneshot(owner_revocation_request(
            &owner_token,
            serde_json::json!({ "subject": APP_CLIENT_ID }),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::NO_CONTENT);

    let res = refresh(&g, APP_CLIENT_ID, "app-refresh").await;
    assert_eq!(res.status(), StatusCode::BAD_REQUEST);
    assert_eq!(
        body_json(res.into_body()).await,
        serde_json::json!({
            "error": "invalid_grant",
            "error_description": "Refresh token has been revoked",
        })
    );
    assert_eq!(
        refresh(&g, OTHER_CLIENT_ID, "other-refresh").await.status(),
        StatusCode::OK,
        "another client's epoch is its own"
    );
}
}
