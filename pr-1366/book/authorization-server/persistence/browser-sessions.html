Browser Sessions

Covers authorization-server-rust/src/db/browser_sessions.rs

Two tables hold what the server knows about the browsers it has let in. browser_sessions holds one row per browser session, keyed by its sid, read back as a BrowserSession, one field to one column of the same name. scopes is compact JSON text through the shared JsonStrings; kind is its wire string, same_device or paired, which a CHECK on the column also enforces.

A session’s row outlives the session. Revoking it stamps revoked_at and keeps the row, because the token verifier and a refresh look the sid up to refuse what the session minted. The row goes only in the retention sweep, purge_expired, with the cutoff now less BROWSER_SESSION_RETENTION.

session_shortfall_acknowledgements records, per session, the apps it has gone on past its limited page for. Its primary key is the pair (sid, client_id), so a pair is recorded at most once and a lookup by the pair is a key lookup. Neither table carries a foreign key: sid here, and on the requests, codes and refresh families that record it, is a soft reference the retention sweep keeps tidy.

The tests open a store with store.
