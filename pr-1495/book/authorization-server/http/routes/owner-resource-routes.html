These routes are the Owner’s view of what they have let in, and the switches to take it back: the standing grants apps hold, the apps themselves, and the browsers the server has signed in. The Owner’s access-management screens call them with the Owner’s token.

They live under /authorization, behind require_valid_session, and are uncached. Each handler takes its capability through Scoped<…>, which needs one scope per resource and permission: wildflower/Grant.r and .d, wildflower/Client.r and .u, wildflower/BrowserSession.r and .d. A token without it gets a 403 naming the missing scope, before the handler runs. The Owner’s scopes cover every one of them. The capability is the only way to the store, so the scope can’t be skipped.

http::routes::grants

Owner-scoped /grants management routes — list, fetch, and revoke standing client grants. One module per route handler (list_all, get_by_id, revoke_by_id), each exposing a MethodRouter; router() is the only path table. The two methods on /grants/{id} (GET + DELETE) are merged here onto the shared path.

router

The /grants route table: GET /grants lists, and /grants/{id} answers both GET and DELETE.

#![allow(unused)]
fn main() {
pub fn router() -> Router<Arc<AuthorizationServerState>> {
    Router::new().route("/grants", list_all::route()).route(
        "/grants/{id}",
        get_by_id::route().merge(revoke_by_id::route()),
    )
}
}

revoke_by_id

Revoking a grant takes back everything it let the app hold. The grants revoker’s revoke owns the cascade: the grant is deleted, the app’s refresh-token families are expired, and its revocation epoch moves to now, so its live access tokens die too. It needs wildflower/Grant.d alone, not wildflower/Token.d.

DELETE /authorization/grants/{id} — revoke a grant, expire the refresh-token families minted under its client, and bump the client’s revocation epoch so any still-live access tokens die too — no offline_access client (or a leaked live bearer) outlives the revocation. }
}

http::routes::clients

Owner-scoped /clients management routes — list registered OAuth clients and PATCH one’s disabledAt to disable or re-enable it. One module per route handler (list_all, update_by_id); openapi_router() is the only path table.

Unlike the rest of /authorization, these routes are documented: they’re built as an OpenApiRouter so the committed OpenAPI snapshot (and the TS drift test against authorization-core) cover them. crate::http splits it — the axum half is mounted under /authorization behind the session gate, the spec half is nested under /authorization in the documented surface.

openapi_router

The /clients route table, as an OpenApiRouter so the spec is collected from the routes that serve traffic.

#![allow(unused)]
fn main() {
pub(crate) fn openapi_router() -> OpenApiRouter<Arc<AuthorizationServerState>> {
    OpenApiRouter::new()
        .routes(routes!(list_all::handle_list_clients))
        .routes(routes!(update_by_id::handle_update_client))
}
}

update_by_id

The one thing the Owner may change about an app is whether it is disabled. Any time sent disables the app now, stamped with the server’s clock, so a disable can’t be scheduled or backdated. The clients disabler’s set_disabled_at is what refuses an essential app.

Body of PATCH /authorization/clients/{clientId} — the one client field the Owner can edit.

#![allow(unused)]
fn main() {
pub(crate) struct UpdateClientBody {
    /// Any time to disable the client now, or `null` to re-enable it. The
    /// server stamps its own now whatever time is sent, so a disable can't be
    /// scheduled or backdated. Required, `null` included.
    // `Option::deserialize` stops serde reading a missing field as `null`, so an
    // empty body can't re-enable a client by omission.
    disabled_at: Option<DateTime<Utc>>,
}
}

authorization-server-rust/src/http/routes/clients/update_by_id.rs lines 20–29 · authorization-server in the code index

PATCH /authorization/clients/{clientId} — disable (stamped with the server’s now, whatever time is sent) or re-enable a client by writing its disabledAt; answers with the client as stored. A disabled client is refused at /oauth/authorize and /oauth/token. Idempotent (a client that already has a disabledAt keeps it). Disabling an essential client — the host app’s or the browser-session client — is refused with 409 EssentialClient. Acquired through LiveClientsDisabler (scope wildflower/Client.u).

#![allow(unused)]
fn main() {
pub(super) async fn handle_update_client(
    clients: Scoped<LiveClientsDisabler>,
    Path(client_id): Path<String>,
    Json(body): Json<UpdateClientBody>,
) -> Result<Json<ClientBody>, AuthorizationServerError> {
    let stamp = body.disabled_at.map(|_sent| Utc::now());
    let updated = clients.set_disabled_at(&client_id, stamp)?;
    Ok(Json(updated.into()))
}
}

list_all

Every browser signed in right now, newest first, each marked when it is the caller’s own. The browser sessions reader’s list_live gives the list. The caller’s sid comes from Authenticated<LiveSessionReader>, which reads only the caller’s own claims.

A live browser session as the Owner’s “Browsers” list reads it. Every column of the browser_sessions row but its scopes and revoked_at (always null on a live one), plus heldByCaller: whether the caller’s own token was minted under it.
