OAuth Consents

Covers authorization-server-rust/src/domain/capabilities/access/consents/oauth.rs

An app has sent a browser to /oauth/authorize, and its code request is parked, waiting for a decision. This page is that decision, as the consent card and the Owner’s popup drive it: read the prompt, ask the Owner about it, approve it, deny it. The capabilities are declared on Consents.

Every operation starts by loading the prompt, and then resolves it against the app’s registration as it stands now, through the same ResolvedCodeRequest /oauth/authorize used to park it, so the card can’t disagree with the endpoint. A prompt whose app has been disabled is never read and never approved: reading it is not found, and approving it denies it.

An approval writes through the writers, inside the decider’s one write scope: the request approver issues the code, bounded by the browser session the request was made in, and the grant recorder records the standing grant and, for an app trusted on first use, its registration. So the code, the grant and the registration land together or not at all.

The tests decide through a decider built over the consent fixtures.

#![allow(unused)]
fn main() {
pub(crate) fn oauth_consent(
    &self,
    id: &str,
    now: DateTime<Utc>,
) -> Result<OAuthConsentView, AuthorizationServerError> {
    self.store.read(|tx| {
        let pending_request = load_pending_code_request(tx, id, now)?;
        let resolved = resolve(tx, &pending_request)?;
        if resolved.is_client_disabled() {
            return Err(consent_not_found(id));
        }
        Ok(OAuthConsentView {
            missing_approval_scopes: resolved
                .approvable_scopes()
                .missing_approval_scopes(&self.reader_grant),
            client_name: resolved.client_name().to_owned(),
            presented_client_change: resolved.presented_client_change().clone(),
            pending_request,
        })
    })
}
}

ConsentRaiser

raise_for_owner

A browser that can read a prompt but not approve it hands it to the Owner. The request’s own raise_for_owner transition is written through the guarded replace, so a request decided meanwhile is not found.

Raise the pending authorization-code prompt id for the Owner and republish the Owner prompt, once may_raise_for_owner admits it: the authorization start limit, as for a request /oauth/authorize raises, so asking the Owner about request after request costs what starting them would have. A prompt not decidable in its requesting browser is already raised: nothing changes and the limit isn’t asked.

Errors

AuthorizationServerError::OAuthConsentNotFound when id names no live code-flow prompt, or its client is disabled (the rule on OwnerPrompt).

#![allow(unused)]
fn main() {
pub(crate) fn raise_for_owner(
    &self,
    id: &str,
    may_raise_for_owner: impl FnOnce() -> bool,
    now: DateTime<Utc>,
) -> Result<OwnerRaising, AuthorizationServerError> {
    let raising = self.store.write(|tx| {
        let pending_request = load_pending_code_request(tx, id, now)?;
        if tx.is_client_disabled(&pending_request.client_id)? {
            return Err(consent_not_found(id));
        }
        if !pending_request.decidable_in_requesting_browser {
            return Ok(OwnerRaising::AlreadyRaised);
        }
        if !may_raise_for_owner() {
            return Ok(OwnerRaising::StartLimited);
        }
        let raised = pending_request
            .raise_for_owner(now)
            .map_err(|_| consent_not_found(id))?;
        if tx.replace_code_request(&pending_request, &raised)? {
            Ok(OwnerRaising::Raised)
        } else {
            Err(consent_not_found(id))
        }
    })?;
    if raising == OwnerRaising::Raised {
        self.owner_approval.republish_active();
    }
    Ok(raising)
}
}

approve_oauth_consent

Approve the authorization-code consent prompt id: clamp the Owner’s ticks into a DelegatedScopes proof (which requires the approver’s approval scopes), issue the code, record the standing grant and, for a client trusted on first use, its registration, all in one write scope, so the code, the grant and the registration land together or not at all; once it commits, republish the Owner prompt and return the client callback URL. approve_oauth_in

approve_oauth_consent’s flow, inside its write scope tx. The checks run in order: a disabled client’s prompt is denied; the DelegatedScopes proof comes first after that, so an approver lacking an approval scope is refused before anything else; then the acknowledgement of a registration change; then the launch’s patient. Each refusal is an error that writes nothing, and only then does a clamp that left nothing become a deny.

#![allow(unused)]
fn main() {
fn approve_oauth_in(
    &self,
    tx: &mut impl GrantTx,
    id: &str,
    input: ApproveOAuthConsentInput,
    generate_code: impl FnOnce() -> String,
    now: DateTime<Utc>,
) -> Result<ConsentOutcome, AuthorizationServerError> {
    let pending_request = load_pending_code_request(tx, id, now)?;
    let requested_redirect_uri = &pending_request.redirect_uri;
    let resolved = resolve(tx, &pending_request)?;
    // The client was disabled since the request was made: it can't be
    // approved, so it ends here, and the app hears why.
    if resolved.is_client_disabled() {
        deny_pending_request(tx, &pending_request, now, id)?;
        return Ok(denial_outcome(
            &pending_request,
            AuthorizeRefusal::DisabledClient.description(),
        ));
    }
    // The proof every write below demands: the approver holds this prompt's
    // approval scopes, and the Owner's approval is clamped to what this
    // prompt may grant and covered by the approver's own grant. Taken
    // first, so an approver lacking an approval scope is refused before
    // anything else.
    let maybe_delegated_scopes = DelegatedScopes::clamp(
        &self.approver_grant,
        input.owner_approved_scopes,
        resolved.approvable_scopes(),
    )?;
    if resolved
        .presented_client_change()
        .would_change_registration()
        && !input.acknowledged_registration_change
    {
        return Err(AuthorizationServerError::RegistrationNotAcknowledged {
            id: id.to_owned(),
        });
    }
    if !pending_request.admits_patient(input.patient.as_deref()) {
        return Err(AuthorizationServerError::LaunchPatientMismatch { id: id.to_owned() });
    }
    let Some(delegated_scopes) = maybe_delegated_scopes else {
        deny_pending_request(tx, &pending_request, now, id)?;
        return Ok(denial_outcome(
            &pending_request,
            REQUEST_DECLINED_DESCRIPTION,
        ));
    };

    let issued_code = match RequestApprover::within(tx).approve_for_code(
        CodeAuthority::OwnerDelegated(&delegated_scopes),
        &pending_request,
        input.patient.as_deref(),
        generate_code(),
        &self.stale_session_cutoff,
        now,
    )? {
        CodeApproval::Issued(issued_code) => issued_code,
        CodeApproval::RequestNotPending => return Err(consent_not_found(id)),
        // The approver denied the request instead: tell the client so.
        CodeApproval::BrowserSessionEnded => {
            return Ok(denial_outcome(
                &pending_request,
                BROWSER_SIGNED_OUT_DESCRIPTION,
            ));
        }
    };
    GrantRecorder::within(tx).record_code_grant(
        &pending_request.client_id,
        requested_redirect_uri,
        &delegated_scopes,
        input.patient.as_deref(),
        now,
    )?;
    Ok(ConsentOutcome::Approved {
        redirect: Some(build_client_redirect_url(
            requested_redirect_uri,
            &issued_code.code,
            &pending_request.client_state,
        )),
    })
}
}
