Grant Recorder

Covers authorization-server-rust/src/domain/capabilities/writers/grant_recorder.rs

When the Owner approves an app, the approval leaves a standing grant behind, so the app’s next request for the same access goes through without asking. The grant recorder writes it: it creates the grant, or widens the one already standing. For an app trusted on first use it also writes the app’s registration, which the approval is what justifies.

Both writes take delegated scopes. A grant row and a widened registration only ever carry scopes an approver was entitled to delegate, and a scope the Owner unticked is added to neither. The proof also says whether to write the registration at all (would_write_registration).

record_code_grant

One grant per app and redirect: a re-approval widens the grant that stands, never adds a second. The widening is the grant’s own absorb_reapproval.

Register (or widen) the client and insert or cumulatively update the standing authorization-code grant for (client_id, redirect_uri), in the caller’s write scope: write the clients row when the proof writes the registration, then read the standing grant — if present, fold the re-approval in via CumulativeConsent::absorb_reapproval and write it back; otherwise mint a fresh grant. The scope holds the write lock from before the read, so two concurrent approvals serialise at the read rather than both reading the pre-merge row and one losing its scope union, and the registration lands with the grant it justifies or not at all.

For a client trusted on first use the clients row, as read inside the transaction, is created when absent, otherwise widened in place, and the approved redirect joins its allowlist exactly when the row doesn’t already allow it. The proof’s approver held both wildflower/Client.c and wildflower/Client.u, so whichever the row calls for is covered. A fixed registration, which an approval never writes, gets no clients row at all.

The grant (and any widened registration) records exactly the proof’s scopes, so a scope the approver pruned is never added to either.

Errors

AuthorizationServerError::Infrastructure on a store failure, which rolls the caller’s scope back.

#![allow(unused)]
fn main() {
pub(crate) fn record_code_grant(
    &mut self,
    client_id: &str,
    redirect_uri: &Url,
    delegated_scopes: &DelegatedScopes,
    patient: Option<&str>,
    now: DateTime<Utc>,
) -> Result<(), AuthorizationServerError> {
    let delegated = delegated_scopes.scopes();
    if delegated_scopes.would_write_registration() {
        write_registration(self.tx, client_id, redirect_uri, delegated, now)?;
    }
    match self
        .tx
        .grant_by_client_and_redirect(client_id, redirect_uri)?
    {
        Some(mut grant) => {
            grant.absorb_reapproval(delegated, patient, now);
            self.tx.update_authorization_code_grant(&grant)
        }
        None => self
            .tx
            .create_authorization_code_grant(&AuthorizationCodeGrant {
                id: Uuid::new_v4().to_string(),
                client_id: client_id.to_owned(),
                scopes: delegated.to_vec(),
                granted_at: now,
                last_used_at: None,
                patient: patient.map(str::to_owned),
                redirect_uri: redirect_uri.clone(),
            }),
    }
}
}

fn main() {
fn a_new_grant_starts_unused_and_a_reapproval_keeps_its_last_use() {
    let store = FakeGrantStore::default();
    let record = || {
        let mut tx = store.tx();
        let mut recorder = GrantRecorder::within(&mut tx);
        recorder
            .record_code_grant(
                "client-a",
                &redirect(),
                &delegated_scopes(&["openid"]),
                None,
                Utc::now(),
            )
            .unwrap();
        recorder
            .record_device_grant(
                "client-a",
                "Kitchen iPad",
                &delegated_scopes(&["openid"]),
                None,
                Utc::now(),
            )
            .unwrap();
    };
    let code_grant = || {
        store
            .tx()
            .grant_by_client_and_redirect("client-a", &redirect())
            .unwrap()
            .expect("code grant")
    };
    let device_grant = || {
        store
            .tx()
            .device_grant_by_client_and_device_name("client-a", "Kitchen iPad")
            .unwrap()
            .expect("device grant")

        .stamp_device_grant_used(&device_grant().id, used_at)
        .unwrap();

    assert_eq!(device_grant().last_used_at, Some(used_at));

write_registration

The store’s upsert updates the row in place, keeping its registration time and any disabled_at, so a widening never brings a disabled app back.

Create the clients row for client_id, or widen the existing one, by the delegated scopes and (when the row doesn’t allow it yet) the redirect — inside the caller’s transaction, after reading the row under its write lock, so the write follows the row as it stands, not as an earlier read saw it. The store’s upsert keeps the row’s registration time and disabled_at, so a widening never brings a disabled client back.

#![allow(unused)]
fn main() {
fn write_registration<T: GrantTx>(
    tx: &mut T,
    client_id: &str,
    redirect_uri: &Url,
    delegated: &[String],
    now: DateTime<Utc>,
) -> Result<(), AuthorizationServerError> {
    let row = match tx.client_by_id(client_id)? {
        Some(existing_client) => {
            let adds_redirect = !existing_client.allows_redirect_uri(redirect_uri);
            widen_registration(existing_client, redirect_uri, delegated, adds_redirect)
        }
        None => new_registration(client_id, redirect_uri, delegated, now),
    };
    // `upsert_client` updates in place, preserving `registered_at` and any admin
    // `disabled_at` — a widening never resurrects a disabled client.
    tx.upsert_client(&row)
}
}

new_registration

The clients row a first approval of an unregistered client creates: a public client named after its own client_id (there is no registrar to have supplied a display name), holding only the redirect it just used and the scopes the approver actually granted.

The scopes go in collapsed, through the same widened_scopes the widening path uses (against an empty registration), so a row created by a first approval and a row widened into the same state are byte-identical — the approval order can’t leave two clients with differently-spelled but equivalent ceilings.

        registered_at: now,

widen_registration

The scopes widen by meaning, through widened_scopes, and the row is only ever read by coverage, as in PresentedClientChange, so a collapsed row admits exactly what the uncollapsed one would.

Widen an existing registration by what the approver just approved: append the redirect_uri as an absolute entry when it resolved to none of the existing ones, and widen allowed_scopes by the granted scopes. Everything else on the row (its name, kind, secret, registration time) is left exactly as it was.

The scope half is wildflowerhealthio_scopes::widened_scopes, not a string union: the granted scopes are parsed, so an approval that grants patient/Patient.cruds replaces a registered patient/Patient.r instead of leaving the row carrying both, and granting again what the row already covers leaves it untouched. allowed_scopes is only ever read through wildflowerhealthio_scopes::allowed_scope_covers (at /authorize, at /device_authorization, and in PresentedClientChange::from_presented_registration), so a collapsed row admits exactly the requests the un-collapsed one did.

#![allow(unused)]
fn main() {
fn widen_registration(
    mut client: Client,
    redirect_uri: &Url,
    granted_scopes: &[String],
    adds_redirect: bool,
) -> Client {
    if adds_redirect {
        client.redirect_uris.push(redirect_uri.clone());
    }
    client.allowed_scopes = widened_scopes(&client.allowed_scopes, granted_scopes);
    client
}
}
