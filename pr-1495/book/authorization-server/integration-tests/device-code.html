Device Code

Covers authorization-server-rust/tests/integration/device_code.rs

The device-code flow (RFC 8628) is for a device with no browser of its own to send to /oauth/authorize: a TV, a watch, a command line. The device asks at /oauth/device_authorization, shows its user a short code, and polls /oauth/token. The Owner enters the code on the Device Page and approves. Until then the device hears “not yet”.

The request is a DeviceRequest, one of the polled requests. The Owner’s approval is recorded twice. The request carries the approval the poll redeems (DeviceRequest::approve). A standing DeviceGrant is what the Owner’s list of authorized devices shows.

The file also holds the token endpoint’s refresh-token promises, for both flows: rotation, the family’s deadline, binding to the client, and what revoking a grant does to its client’s refresh tokens.

device_consent_clamps_granted_scopes_to_client_allowed

Device-flow consent clamps the granted scopes to the client’s current allowed_scopes, not just to what the request asked for: a request that asked for write while it was permitted grants no write once the client’s registration no longer allows it.

#![allow(unused)]
fn main() {
async fn device_consent_clamps_granted_scopes_to_client_allowed() {
    let (g, owner_token, db) = spin_up();
    // The client permits only `read`.
    seed_client_with_redirect(&db, "device-client", "https://app.example/cb", &["read"]);
    // A pending device request that asks for the disallowed `write` too.
    plant_device_request(
        &store_handle(&db),
        "device-client",
        "dev-clamp",
        &["read", "write"],
        RequestStatus::Pending,
        Utc::now() + Duration::minutes(5),
    );

    // The Owner approves both scopes; the handler must drop `write`.
    let approve = build_request(
        Request::post("/authorization/devices/WILD-FLWR/approve")
            .header("host", "127.0.0.1")
            .header("authorization", format!("Bearer {owner_token}"))
            .header("content-type", "application/json"),
        Body::from(r#"{"approvedScopes":["read","write"]}"#),
    );
    let res = g.router.clone().oneshot(approve).await.expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);
    assert_eq!(
        body_json(res.into_body()).await,
        serde_json::json!({ "status": "approved" })
    );

    // The issued token carries only the still-allowed `read`, never `write`.
    let body = "grant_type=urn%3Aietf%3Aparams%3Aoauth%3Agrant-type%3Adevice_code&\
                client_id=device-client&device_code=dev-clamp";
    let res = post_form(&g.router, "/oauth/token", body).await;
    assert_eq!(res.status(), StatusCode::OK);
    let token = body_json(res.into_body()).await;
    assert_eq!(token["scope"], "read");
}
}

device_consent_allows_expansion_beyond_requested

Device-flow consent is expandable: the Owner approving a device may grant scopes the device never requested, up to the client’s allowed_scopes. The code flow stays clamped to the requested scopes, so a third-party app can’t widen its own grant; device_consent_clamps_granted_scopes_to_client_allowed holds the allowed-scopes ceiling.

#![allow(unused)]
fn main() {
async fn device_consent_allows_expansion_beyond_requested() {
    let (g, owner_token, db) = spin_up();
    // The client is allowed both read and write.
    seed_client_with_redirect(
        &db,
        "device-client",
        "https://app.example/cb",
        &["read", "write"],
    );
    // ...but the device requested only `read`.
    plant_device_request(
        &store_handle(&db),
        "device-client",
        "dev-expand",
        &["read"],
        RequestStatus::Pending,
        Utc::now() + Duration::minutes(5),
    );

    // The Owner grants the un-requested-but-allowed `write` on top of `read`.
    let approve = build_request(
        Request::post("/authorization/devices/WILD-FLWR/approve")
            .header("host", "127.0.0.1")
            .header("authorization", format!("Bearer {owner_token}"))
            .header("content-type", "application/json"),
        Body::from(r#"{"approvedScopes":["read","write"]}"#),
    );
    let res = g.router.clone().oneshot(approve).await.expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);
    assert_eq!(
        body_json(res.into_body()).await,
        serde_json::json!({ "status": "approved" })
    );

    // The expansion is persisted onto the grant — `write` was never requested.
    let request = store_handle(&db)
        .read(|tx| tx.device_request_by_id("dev-expand"))
        .expect("query request")
        .expect("request present");
    let granted = &request
        .state
        .approval()
        .expect("granted scopes")
        .granted_scopes;
    assert!(granted.contains(&"read".to_string()));
    assert!(granted.contains(&"write".to_string()));
}
}

device_approval_mints_durable_grant_and_links_refresh_family

Approving a device-code consent records a standing device grant, the record the Owner’s list of authorized devices shows, and the family the device’s offline_access token starts links back to that grant. This is the device half of “a refresh family names the grant that earned it”; offline_access_issues_rotating_refresh_token is the code-flow half.

#![allow(unused)]
fn main() {
async fn device_approval_mints_durable_grant_and_links_refresh_family() {
    let (g, owner_token, db) = spin_up();
    seed_client_with_redirect(
        &db,
        "device-client",
        "https://app.example/cb",
        &["read", "offline_access"],
    );
    plant_device_request(
        &store_handle(&db),
        "device-client",
        "dev-durable",
        &["read", "offline_access"],
        RequestStatus::Pending,
        Utc::now() + Duration::minutes(5),
    );

    // Approve, naming the device.
    let approve = build_request(
        Request::post("/authorization/devices/WILD-FLWR/approve")
            .header("host", "127.0.0.1")
            .header("authorization", format!("Bearer {owner_token}"))
            .header("content-type", "application/json"),
        Body::from(r#"{"approvedScopes":["read","offline_access"],"deviceName":"Reception iPad"}"#),
    );
    let res = g.router.clone().oneshot(approve).await.expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);

    // The standing device grant shows in the access index as the `device_code`
    // union variant, titled by its deviceName.
    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::get("/authorization/grants")
                .header("host", "127.0.0.1")
                .header("authorization", format!("Bearer {owner_token}")),
            Body::empty(),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);
    let grants = body_json(res.into_body()).await;
    let device_grant = grants
        .as_array()
        .expect("grants array")
        .iter()
        .find(|grant| grant["grantType"] == "device_code")
        .expect("a device grant was minted");
    assert_eq!(device_grant["deviceName"], "Reception iPad");
    assert_eq!(device_grant["clientId"], "device-client");
    let scopes = device_grant["scopes"].as_array().expect("scopes array");
    assert!(scopes.iter().any(|scope| scope == "read"));
    assert!(scopes.iter().any(|scope| scope == "offline_access"));

    // Redeeming the device_code issues the offline_access refresh token, whose
    // family links back to the device grant just minted.
    let body = "grant_type=urn%3Aietf%3Aparams%3Aoauth%3Agrant-type%3Adevice_code&\

    assert_eq!(res.status(), StatusCode::OK);
    let refresh = body_json(res.into_body()).await["refresh_token"]
        .as_str()
        .expect("offline_access refresh token")
        .to_string();

    let (_, family) = store_handle(&db)
        .read(|tx| tx.refresh_token_with_family_by_hash(&token_storage_hash(&refresh)))
        .expect("family query")
        .expect("family present");
    assert_eq!(
        family.grant_id.as_deref(),
        Some(device_grant["id"].as_str().expect("grant id")),
    );
}

        .expect("lastUsedAt is set")

offline_access_issues_rotating_refresh_token

Granting offline_access issues a rotating refresh token, and the full rotation contract holds: redeeming swaps generations, replaying a consumed generation revokes the whole family (OAuth 2.1 rotation semantics), so the rotated-to token dies with it. The family records the app’s standing grant.

#![allow(unused)]
fn main() {
async fn offline_access_issues_rotating_refresh_token() {
    let (g, owner_token, db) = spin_up();
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["read", "offline_access"],
    );
    let request_id = authorize_and_approve(
        &g,
        &owner_token,
        &db.paired_browser_token,
        "test-app",
        "read%20offline_access",
        r#"{"approvedScopes":["read","offline_access"],"acknowledgedRegistrationChange":false}"#,
    )
    .await;

    // Pull the redeemable code off the status poll, then redeem it.
    let res = get_authorization_status(&g.router, &db.paired_browser_token, &request_id).await;
    assert_eq!(res.status(), StatusCode::OK);
    let status = body_json(res.into_body()).await;
    let redirect = status["redirect"].as_str().expect("redirect");
    let code = Url::parse(redirect)
        .expect("redirect url")
        .query_pairs()
        .find(|(k, _)| k == "code")
        .map(|(_, v)| v.into_owned())
        .expect("code param");
    let body = format!(
        "grant_type=authorization_code&client_id=test-app&code={code}&\
         code_verifier={CODE_VERIFIER}&redirect_uri=https%3A%2F%2Fapp.example%2Fcb"
    );
    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::post("/oauth/token")
                .header("content-type", "application/x-www-form-urlencoded"),
            Body::from(body),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);
    let token = body_json(res.into_body()).await;
    assert_eq!(token["scope"], "read offline_access");
    let first_refresh = token["refresh_token"]
        .as_str()
        .expect("refresh_token present with offline_access")
        .to_string();

    // The minted family records the authorization-code grant that authorized
    // it, as a device family records its device grant.
    {
        let store = store_handle(&db);
        let grant = store
            .read(|tx| {
                tx.grant_by_client_and_redirect(
                    "test-app",
                    &Url::parse("https://app.example/cb").unwrap(),
                )
            })
            .expect("grant query")
            .expect("code grant minted at approval");
        let (_, family) = store
            .read(|tx| tx.refresh_token_with_family_by_hash(&token_storage_hash(&first_refresh)))
            .expect("family query")
            .expect("family present");
        assert_eq!(family.grant_id.as_deref(), Some(grant.id.as_str()));
    }

    // Redeem the refresh token: fresh access token + the next generation.
    let body = format!("grant_type=refresh_token&client_id=test-app&refresh_token={first_refresh}");
    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::post("/oauth/token")
                .header("content-type", "application/x-www-form-urlencoded"),
            Body::from(body.clone()),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);
    let refreshed = body_json(res.into_body()).await;
    assert_eq!(refreshed["token_type"], "Bearer");
    assert_eq!(refreshed["scope"], "read offline_access");
    assert!(!refreshed["access_token"]
        .as_str()
        .expect("access_token")
        .is_empty());
    let second_refresh = refreshed["refresh_token"]
        .as_str()
        .expect("rotated refresh_token")
        .to_string();
    assert_ne!(second_refresh, first_refresh);

    // Replaying the consumed generation is treated as theft …
    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::post("/oauth/token")
                .header("content-type", "application/x-www-form-urlencoded"),
            Body::from(body),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::BAD_REQUEST);
    assert_eq!(
        body_json(res.into_body()).await,
        serde_json::json!({
            "error": "invalid_grant",
            "error_description": "Refresh token has been revoked",
        })
    );

    // … which kills the whole family: the rotated-to token is dead too. The
    // family is expired in place (not deleted), so it reports as expired.
    let body =
        format!("grant_type=refresh_token&client_id=test-app&refresh_token={second_refresh}");
    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::post("/oauth/token")
                .header("content-type", "application/x-www-form-urlencoded"),
            Body::from(body),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::BAD_REQUEST);
    assert_eq!(
        body_json(res.into_body()).await,
        serde_json::json!({
            "error": "invalid_grant",
            "error_description": "Refresh token has expired",
        })
    );
}
