Authorization Start Limit

Covers authorization-server-rust/tests/integration/authorization_start_limit.rs

Anyone who knows the server’s domain can start an authorization request, and every request raised for the Owner pops up on the Owner’s device. So the host keeps a limit, its AuthorizationStartGate. Every start that may bother the Owner spends from the limit once; a start the limit refuses is 429, uncached, and parks nothing.

The layer limit_authorization_starts sits on /oauth/authorize and /oauth/device_authorization only. When a start asks depends on what it carries:

  • A live browser session that can decide consents, at /oauth/authorize, asks only when its request is to be raised for the Owner (CodeRequest::raise_for_owner) or parked for the limited page. One it decides on its own Consent Card spends nothing, and going on past the limited page (CodeRequest::acknowledge_session_shortfall) asks nothing more.
  • No live browser session, at /oauth/authorize, never asks: the browser is only sent to pairing.
  • Anything else, and every device-authorization start, asks at once, before the request is parsed.

Asking the Owner about a request already parked (…/ask-owner) spends from the same limit, when it raises the request.

a_refused_start_is_429_uncached_before_it_is_parsed_on_either_route

A refused start is 429, uncached, on either route, before the request is parsed: both requests here are malformed, and admitted each would be a 400.

#![allow(unused)]
fn main() {
async fn a_refused_start_is_429_uncached_before_it_is_parsed_on_either_route() {
    let gate = CountingGate::refusing();
    let (g, _owner_token, db) = spin_up_with_authorization_start_gate(gate.clone());
    let paired_browser_cookie = browser_session_cookie(&db.paired_browser_token);

    // Neither request is well-formed: admitted, each would be a `400`.
    for (method, path, cookie) in [
        (
            Method::GET,
            "/oauth/authorize",
            Some(paired_browser_cookie.as_str()),
        ),
        (Method::POST, "/oauth/device_authorization", None),
    ] {
        let res = send(&g, method, path, cookie).await;
        assert_eq!(res.status(), StatusCode::TOO_MANY_REQUESTS, "{path}");
        assert_eq!(
            res.headers()
                .get(header::CACHE_CONTROL)
                .and_then(|value| value.to_str().ok()),
            Some("no-store"),
            "{path}"
        );
        assert_eq!(
            body_string(res.into_body()).await,
            "too many authorization requests; try again later"
        );
    }
    assert_eq!(gate.asked(), 2);
}
}

a_browser_without_a_session_is_sent_to_pairing_without_asking_the_gate

A browser without a session, or whose cookie holds no live session, is only sent to pairing by /oauth/authorize, so it passes without asking the gate: a flood of them can’t spend the allowance a paired browser’s requests need. A device authorization without a session still asks.

    let gate = CountingGate::refusing();
    let (g, _owner_token, db) = spin_up_with_authorization_start_gate(gate.clone());
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let authorize = format!(
        "/oauth/authorize?{}",
        authorize_query("test-app", REQUESTED_SCOPES)
    );

    for cookie in [None, Some("__Host-browser_session=not-a-token")] {
        let res = send(&g, Method::GET, &authorize, cookie).await;
        assert_eq!(res.status(), StatusCode::FOUND, "{cookie:?}");
        assert!(
            location_of(&res).starts_with("pair?next="),
            "{cookie:?} is sent to pairing"
        );

    assert_eq!(gate.asked(), 0);

    let res = send(&g, Method::POST, "/oauth/device_authorization", None).await;
    assert_eq!(res.status(), StatusCode::TOO_MANY_REQUESTS);
    assert_eq!(gate.asked(), 1);
}
}

a_deciding_browser_s_request_parked_for_the_limited_page_asks_the_gate

A deciding browser whose session falls short of the request asks the gate, which its start deferred, before the request parks for the limited page; admitted, going on past the page raises the request for the Owner without asking again. Refused, a request for another app parks nothing.

#![allow(unused)]
fn main() {
async fn a_deciding_browser_s_request_parked_for_the_limited_page_asks_the_gate() {
    let gate = Arc::new(CountingGate {
        admitted: 1,
        asked: AtomicUsize::new(0),
    });
    let (g, _owner_token, db) = spin_up_with_authorization_start_gate(gate.clone());
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let same_device_session_token = signed_in_same_device_session_token(&g).await;
    let sid = decode_jwt_payload(&same_device_session_token)["sid"]
        .as_str()
        .expect("a browser session's token names its sid")
        .to_owned();
    let deciding_scopes = [
        "wildflower/AuthorizationRequest.r",
        "wildflower/AuthorizationRequest.u",
    ];
    let session_token = mint_browser_session_token(&db, &sid, &deciding_scopes);
    narrow_browser_session_of(&db, &session_token, &deciding_scopes);
    let query = authorize_query("test-app", REQUESTED_SCOPES);

    let request_id = limited_request_id(&get_authorize(&g.router, &session_token, &query).await);
    assert_eq!(gate.asked(), 1);
    let location = continue_past_session_shortfall(&g.router, &session_token, &request_id).await;
    assert_eq!(location, format!("/oauth/authorize/{request_id}/wait"));
    assert_eq!(gate.asked(), 1, "going on asks nothing");

    seed_client_with_redirect(
        &db,
        "other-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let res = get_authorize(
        &g.router,
        &session_token,
        &authorize_query("other-app", REQUESTED_SCOPES),
    )
    .await;
    assert_eq!(res.status(), StatusCode::TOO_MANY_REQUESTS);
    assert_eq!(gate.asked(), 2);
}
}
