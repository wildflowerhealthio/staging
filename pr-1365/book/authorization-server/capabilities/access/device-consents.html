Wildflower, Read in Order

Device Consents

Covers authorization-server-rust/src/domain/capabilities/access/consents/device.rs

The device page is where a code shown somewhere else gets decided. A device (a watch, a TV) shows a user code from the device flow; a browser that isn’t the Owner’s shows one from a browser pairing. Both are polled requests, keyed by their user_code. The approver opens /authorization/devices/{userCode}, sees what is asked, and approves or denies. The capabilities are declared on Consents.

Device consent is expandable: the approver may grant more than the device asked for, up to an envelope. For a device the envelope is the app’s registered scopes; for a browser pairing it is the Owner’s scopes, so no paired browser can hold more than a same-device session. Either way the DelegatedScopes clamp also bounds every resource scope by what the approver holds.

A device approval records a standing device grant, keyed by the app and the device’s name, through the grant recorder. A pairing records no grant: the pairing page’s poll starts the paired session once the request is approved. Neither approval has a callback to send a browser to; the device or the pairing page learns the decision by polling.

The tests decide through the consent fixtures.

fn load_pending_request_by_user_code(
    tx: &mut impl AuthorizationRequestsTx,
    user_code: &str,
    now: DateTime<Utc>,
) -> Result<PolledRequest, AuthorizationServerError> {
    tx.pending_polled_request_by_user_code(user_code)?

}

Errors

#![allow(unused)]
fn main() {
pub(crate) fn device_consent(
    &self,
    user_code: &str,
    now: DateTime<Utc>,
) -> Result<DeviceConsentView, AuthorizationServerError> {
    let (request, maybe_existing_client) = self.store.read(|tx| {
        let request = load_pending_request_by_user_code(tx, user_code, now)?;
        let maybe_existing_client = tx.client_by_id(request.client_id())?;
        Ok::<_, AuthorizationServerError>((request, maybe_existing_client))
    })?;
    let (client_name, registered_client_scopes) = match maybe_existing_client {
        Some(existing_client) => (existing_client.name, existing_client.allowed_scopes),
        None => (request.client_id().to_owned(), Vec::new()),
    };
    let (approvable, starting_scopes, approvable_scopes) = match &request {
        PolledRequest::Pairing(_) => {
            let approvable = ApprovableScopes::for_browser_pairing();
            let starting_scopes = approvable.delegable_scopes(&self.reader_grant);
            (approvable, starting_scopes, crate::owner_scopes())
        }
        PolledRequest::Device(_) => (
            ApprovableScopes::for_device(&registered_client_scopes),
            request.requested_scopes().to_vec(),
            registered_client_scopes,
        ),
    };
    Ok(DeviceConsentView {
        request,
        client_name,
        starting_scopes,
        approvable_scopes,
        missing_approval_scopes: approvable.missing_approval_scopes(&self.reader_grant),
    })
}
}

ConsentDecider

approve_device_consent

Approve the device-page consent prompt user_code: apply the expandable scope decision (up to the client’s allowed_scopes for a device, up to OWNER_SCOPES for a browser pairing), transition the request, for a device mint (or refresh) the standing device grant, and republish the Owner prompt. An approval that grants nothing is applied as a deny.

Errors

InsufficientScope when the approver lacks the request’s approval scopes (see ApprovableScopes::missing_approval_scopes: wildflower/Grant.c for a device’s standing grant, which a browser pairing doesn’t record), and InsufficientApproverScope for a resource scope beyond the approver’s own authority, both writing nothing; DeviceConsentNotFound when user_code names no live prompt, names a device request whose client has no row (its envelope), or another surface decided it first.

#![allow(unused)]
fn main() {
pub(crate) fn approve_device_consent(
    &self,
    user_code: &str,
    input: ApproveDeviceConsentInput,
    now: DateTime<Utc>,
) -> Result<ConsentOutcome, AuthorizationServerError> {
    self.decide_and_republish(|tx| {
        match load_pending_request_by_user_code(tx, user_code, now)? {
            PolledRequest::Pairing(request) => {
                self.approve_browser_pairing_in(tx, user_code, &request, input, now)
            }
            PolledRequest::Device(request) => {
                self.approve_device_in(tx, user_code, &request, input, now)
            }
        }
    })
}
}

approve_device_in

The device’s own transition is DeviceRequest::approve, and the grant is named by device_grant_name.

Approve the pending device request request, inside the approval’s write scope tx.

#![allow(unused)]
fn main() {
fn approve_device_in(
    &self,
    tx: &mut impl GrantTx,
    user_code: &str,
    request: &DeviceRequest,
    input: ApproveDeviceConsentInput,
    now: DateTime<Utc>,
) -> Result<ConsentOutcome, AuthorizationServerError> {
    let client = tx
        .client_by_id(&request.client_id)?
        .ok_or_else(|| consent_not_found(user_code))?;
    // The proof every write below demands: the approver holds a device
    // prompt's approval scopes, and the Owner's approval is clamped to what
    // it may grant and covered by the approver's own grant.
    let Some(delegated_scopes) = DelegatedScopes::clamp(
        &self.approver_grant,
        input.owner_approved_scopes,
        &ApprovableScopes::for_device(&client.allowed_scopes),
    )?
    else {
        deny_device_request(tx, request, user_code, now)?;
        return Ok(ConsentOutcome::Denied { redirect: None });
    };
    if !RequestApprover::within(tx).approve_for_device(
        &delegated_scopes,
        request,
        input.patient.as_deref(),
        input.device_name.as_deref(),
        now,
    )? {
        return Err(consent_not_found(user_code));
    }
    let request_device_name = input
        .device_name
        .as_deref()
        .or(request.device_name.as_deref());
    let grant_name = device_grant_name(request_device_name, &client.name);
    GrantRecorder::within(tx).record_device_grant(
        &request.client_id,
        grant_name,
        &delegated_scopes,
        input.patient.as_deref(),
        now,
    )?;
    Ok(ConsentOutcome::Approved { redirect: None })
}
}

deny_device_request

Deny the device request request, as read, at now, in the caller’s write scope tx — an explicit deny, or an approval that grants nothing. It lands only on a request still pending: when another surface decided it first (or it expired) since it was read, nothing changes and the prompt user_code is not found, as an approval that loses the same race is.

#![allow(unused)]
fn main() {
fn deny_device_request(
    tx: &mut impl AuthorizationRequestsTx,
    request: &DeviceRequest,
    user_code: &str,
    now: DateTime<Utc>,
) -> Result<(), AuthorizationServerError> {
    let denied = request
        .deny(now)
        .map_err(|_| consent_not_found(user_code))?;
    if tx.replace_device_request(request, &denied)? {
        Ok(())
    } else {
        Err(consent_not_found(user_code))
    }
}
}
