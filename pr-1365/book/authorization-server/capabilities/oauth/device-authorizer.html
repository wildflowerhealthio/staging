Device Authorizer

Covers authorization-server-rust/src/domain/capabilities/oauth/device_authorizer.rs

A device with no browser of its own can’t send the Owner to a consent card. It asks through the device flow (RFC 8628) instead: it calls POST /oauth/device_authorization and gets two codes back, a secret device_code it keeps and polls /oauth/token with, and a short user_code the Owner confirms at the server’s device page. The device authorizer starts that flow. It parks a pending device request and republishes the Owner prompt, so the host notifies the Owner.

Starting a device authorization grants nothing. The scopes it records are what the device asked for. The Owner’s approval on the device page decides what the device gets, and the token exchanger’s poll mints it. Only an app that has authenticated may start one. Unlike /oauth/authorize, this door doesn’t park a request outside the app’s registration for the Owner: it refuses it.

The tests start authorizations for an authenticated fixture app.

start

The scope check is the authenticated client’s, by coverage.

Check the requested scopes against the client’s allowlist (coverage- aware: a broad grant admits a narrower request it covers), mint the code pair, park the request under device_name (the name the approver sees and the grant is keyed on; None falls back to the client name at approval), and republish the Owner prompt so the host raises the popup.

Errors

DeviceAuthorizationError::ScopeNotAllowed, DeviceAuthorizationError::UserCodeExhausted, or a store failure.

#![allow(unused)]
fn main() {
pub(crate) fn start(
    &self,
    authenticated_client: &AuthenticatedClient,
    requested_scopes: Vec<String>,
    device_name: Option<String>,
    now: DateTime<Utc>,
) -> Result<DeviceCodes, DeviceAuthorizationError> {
    if !authenticated_client.allows_scopes(&requested_scopes) {
        return Err(DeviceAuthorizationError::ScopeNotAllowed);
    }
    // 256-bit CSPRNG opaque token per RFC 6749 §10.10, like an
    // authorization code.
    let device_code = generate_authorization_code();
    let user_code = self
        .store
        .write(|tx| -> Result<_, DeviceAuthorizationError> {
            let user_code = generate_unique_user_code(tx)?
                .ok_or(DeviceAuthorizationError::UserCodeExhausted)?;
            tx.insert_device_request(&DeviceRequest::new(
                NewDeviceRequestArgs {
                    id: device_code.clone(),
                    client_id: authenticated_client.client_id().to_owned(),
                    requested_scopes,
                    ttl: DEVICE_AUTHORIZATION_TTL,
                    user_code: user_code.clone(),
                    device_name,
                },
                now,
            ))?;
            Ok(user_code)
        })?;
    // A fresh pending request is now the Owner prompt; republish so the
    // host notifies it.
    self.owner_approval.republish_active();
    Ok(DeviceCodes {
        device_code,
        user_code,
        expires_in: DEVICE_AUTHORIZATION_TTL.num_seconds(),
        interval: DEVICE_CODE_POLL_INTERVAL.num_seconds(),
    })
}
}

#![allow(unused)]
fn main() {
fn start_parks_a_pending_request_and_raises_the_popup() {
    let store = FakeGrantStore::default();
    let client = authenticated(&store);
    let owner_approval = Arc::new(RecordingOwnerApproval::default());
    let authorizer = DeviceAuthorizer::new(store, owner_approval.clone(), device_page());
    let now = Utc::now();
    let device_codes = authorizer
        .start(
            &client,
            owned_scopes(&["patient/Patient.r", "openid"]),
            Some("Kitchen iPad".to_owned()),
            now,
        )
        .expect("starts");
    assert_eq!(
        device_codes.expires_in,
        DEVICE_AUTHORIZATION_TTL.num_seconds()
    );
    assert_eq!(
        device_codes.interval,
        DEVICE_CODE_POLL_INTERVAL.num_seconds()
    );
    let parked_request = authorizer
        .store
        .tx()
        .polled_request_by_user_code(&device_codes.user_code)
        .unwrap()
        .expect("parked_request under the user code");
    assert_eq!(
        parked_request,
        PolledRequest::Device(DeviceRequest::new(
            NewDeviceRequestArgs {
                id: device_codes.device_code,
                client_id: "app".to_owned(),
                requested_scopes: owned_scopes(&["patient/Patient.r", "openid"]),
                ttl: DEVICE_AUTHORIZATION_TTL,
                user_code: device_codes.user_code,
                device_name: Some("Kitchen iPad".to_owned()),
            },
            now,
        ))
    );
    assert_eq!(owner_approval.count(), 1);
}
}

generate_unique_user_code

A browser pairing draws its user_code here too.

A random user_code that collides with no existing request in tx — pending or terminal, of any flow: reusing a code attached to a denied/expired row would let that stale row shadow the new request at the consent-side lookup. None when every candidate collided.

Errors

The store’s, when reading a candidate’s request fails.

#![allow(unused)]
fn main() {
pub(super) fn generate_unique_user_code(
    tx: &mut impl AuthorizationRequestsTx,
) -> Result<Option<String>, AuthorizationServerError> {
    for _ in 0..MAX_USER_CODE_GENERATION_ATTEMPTS {
        let candidate = {
            let mut rng = rand::rng();
            generate_oauth_user_code(&mut rng)
        };
        if tx.polled_request_by_user_code(&candidate)?.is_none() {
            return Ok(Some(candidate));
        }
    }
    Ok(None)
}
}
