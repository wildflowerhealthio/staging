A browser needs a browser session before it can ask for anything, and it holds one as its browser session cookie. There are two ways to get one, and one way to give it up. A browser that isn’t the Owner’s asks to be paired: it shows a code, and the Owner approves it from somewhere they are already signed in. The Owner’s own browser, on the device the server runs on, is signed in by the base app with a one-time same-device sign-in code. Either kind of browser signs out from the Sign out button on the server’s pages.

Wildflower has no accounts and no passwords. RFC 6749 leaves how a person signs in to an authorization server to the server (§3.1): here, holding the device the server runs on is what makes someone the Owner, and the Owner’s approval is what lets any other browser in. The Browser Pairing, Same-Device Sign-In and Browser Sessions integration tests hold these routes end to end.

http::routes::oauth::browser_pairing

The pairing page makes two calls on its own origin: start a pairing request, then poll it until the Owner decides. Pairing is no OAuth flow, so the bodies are JSON, not form-encoded. A JSON body needs a CORS preflight from any other origin, and the server’s CORS policy never allows credentials, so only the server’s own pages can have a poll’s cookie set.

handle_browser_pairing_start

The browser is named by device_name_from_user_agent, a name the page may change while it polls. The start goes through the browser pairing capability, which parks the pairing and republishes the Owner prompt, so the host notifies the Owner.

Start a browser pairing for this browser, named after its User-Agent, and raise the Owner’s notification. The body’s next is where the browser goes once paired, in practice the /oauth/authorize request it was sent away from.

The answer’s pairing code is the page’s secret, and the user code is for the Owner, who confirms it on the device page: only the page that started the pairing can collect the session. The refusals:

  • next is no path on this server: 400, BrowserPairingNextNotAllowed.
  • The browser-session client is disabled: 403, BrowserSessionClientDisabled.
  • No unused user code could be generated, or a store failed: a logged 500.
#![allow(unused)]
fn main() {
pub(super) async fn handle_browser_pairing_start(
    pairing: Live<LiveBrowserPairing>,
    headers: HeaderMap,
    Json(body): Json<BrowserPairingStartBody>,
) -> Response {
    let user_agent_name = headers
        .get(header::USER_AGENT)
        .and_then(|value| value.to_str().ok())
        .and_then(device_name_from_user_agent);
    let response = match pairing.start(&body.next, user_agent_name, Utc::now()) {
        Ok(started) => Json(StartedBrowserPairingBody::from(started)).into_response(),
        Err(BrowserPairingStartError::NextNotAllowed) => (
            StatusCode::BAD_REQUEST,
            Json(BrowserPairingRefused {
                error: "BrowserPairingNextNotAllowed",
            }),
        )
            .into_response(),
        Err(BrowserPairingStartError::BrowserSessionClientDisabled) => (
            StatusCode::FORBIDDEN,
            Json(BrowserPairingRefused {
                error: "BrowserSessionClientDisabled",
            }),
        )
            .into_response(),
        Err(BrowserPairingStartError::UserCodeExhausted) => InternalError::new(
            "start a browser pairing",
            "exhausted every user_code generation attempt",
        )
        .into_response(),
        Err(BrowserPairingStartError::Store(error)) => {
            InternalError::new("start a browser pairing", error).into_response()
        }
    };
    CacheSuppressed(response).into_response()
}
}

handle_browser_pairing_poll

The poll that finds the pairing approved hands the browser its session. The capability claims the request, stores the approved browser session and mints its token, and the answer sets that token as the cookie through browser_session_set_cookie.

Poll a browser pairing. The poll that finds it approved starts the browser’s paired session and sets it as the browser’s __Host-browser_session cookie. A blank browser_name keeps the name the pairing has. An unknown pairing code is a 404; a store failure, a session that couldn’t be stored, and a token that couldn’t be minted are each a logged 500.

#![allow(unused)]
fn main() {
pub(super) async fn handle_browser_pairing_poll(
    pairing: Live<LiveBrowserPairing>,
    Json(body): Json<BrowserPairingPollBody>,
) -> Response {
    let response = match pairing.poll(&body.pairing_code, &body.browser_name, Utc::now()) {
        Ok(BrowserPairingStatus::Approved { session_token }) => (
            [(
                header::SET_COOKIE,
                browser_session_set_cookie(&session_token, PAIRED_SESSION_TTL),
            )],
            Json(BrowserPairingStatusBody::Approved),
        )
            .into_response(),
        Ok(BrowserPairingStatus::Pending) => {
            Json(BrowserPairingStatusBody::Pending).into_response()
        }
        Ok(BrowserPairingStatus::SlowDown) => {
            Json(BrowserPairingStatusBody::SlowDown).into_response()
        }
        Ok(BrowserPairingStatus::Denied) => Json(BrowserPairingStatusBody::Denied).into_response(),
        Ok(BrowserPairingStatus::Expired) => {
            Json(BrowserPairingStatusBody::Expired).into_response()
        }
        Err(BrowserPairingPollError::NotFound) => (
            StatusCode::NOT_FOUND,
            Json(BrowserPairingNotFound {
                error: "BrowserPairingNotFound",
            }),
        )
            .into_response(),
        Err(BrowserPairingPollError::Store(error)) => {
            InternalError::new("poll a browser pairing", error).into_response()
        }
        Err(BrowserPairingPollError::SessionNotStored(error)) => {
            InternalError::new("store a paired browser session", error).into_response()
        }
        Err(BrowserPairingPollError::Issuance(error)) => {
            InternalError::new("mint a paired browser session's token", error).into_response()
        }
    };
    CacheSuppressed(response).into_response()
}
}

handle_sign_in

The code goes to the same-device sign-in capability, which answers an Owner session’s token and the redirect.

Redeem the code for a same-device session’s token, hand the browser the token as its __Host-browser_session cookie, and 303 it on to next. A next that isn’t allowed, a disabled browser-session client, or a code that is unknown, spent or expired, gets the error page, with no cookie and no redirect.

Every answer is uncached and sends no Referer on, since the request’s own URL carries the code.

#![allow(unused)]
fn main() {
async fn handle_sign_in(
    same_device_sign_in: Live<LiveSameDeviceSignIn>,
    Query(params): Query<SignInParams>,
) -> Response {
    let response = match same_device_sign_in.sign_in(&params.code, &params.next, Utc::now()) {
        Ok(SignedIn {
            session_token,
            redirect,
        }) => (
            StatusCode::SEE_OTHER,
            [
                (header::LOCATION, redirect.location().to_owned()),
                (
                    header::SET_COOKIE,
                    browser_session_set_cookie(&session_token, SAME_DEVICE_SESSION_TTL),
                ),
            ],
        )
            .into_response(),
        Err(SameDeviceSignInError::Refused(refusal)) => refusal_page(refusal),
        Err(SameDeviceSignInError::Store(error)) => {
            InternalError::new("read the browser-session client", error).into_response()
        }
        Err(SameDeviceSignInError::SessionNotStored(error)) => {
            InternalError::new("store the same-device session", error).into_response()
        }
        Err(SameDeviceSignInError::Issuance(error)) => {
            InternalError::new("mint the same-device session's token", error).into_response()
        }
    };
    (
        [(header::REFERRER_POLICY, "no-referrer")],
        CacheSuppressed(response),
    )
        .into_response()
}
}

http::routes::oauth::sign_out

A browser ends its own browser session from the Sign out form on the server’s pages. The cookie alone authenticates it; no bearer is involved. A browser always leaves signed out: one with no cookie, or whose session already ended, has nothing to revoke and gets the same answer.

Nothing here checks where the form came from. The host’s cookie-to-bearer layer refuses a write carrying the cookie from any origin but the server’s own, so another page can’t sign a browser out.

handle_sign_out

The browser session ender revokes the session, which ends everything minted under it, and the answer clears the cookie with browser_session_clearing_set_cookie.

Revoke the browser session the request’s cookie holds, if it holds a standing one, then clear the cookie and 303 to the launcher’s root. The 303 turns the form’s POST into a GET. A browser session that can’t be checked or revoked, because a store can’t be read or written, is a 500 that leaves the cookie as it was.

#![allow(unused)]
fn main() {
async fn handle_sign_out(
    token_verifier: Live<LiveTokenVerifier>,
    browser_session_ender: Live<LiveBrowserSessionEnder>,
    pages: LauncherPages,
    headers: HeaderMap,
) -> Response {
    let session_claims = match carried_browser_session(&token_verifier, &headers) {
        Ok(session_claims) => session_claims,
        Err(error) => {
            return InternalError::new("check the browser session to sign out", error)
                .into_response()
        }
    };
    if let Some(session_claims) = session_claims {
        if let Err(error) = browser_session_ender.end(&session_claims, Utc::now()) {
            return InternalError::new("revoke the browser session", error).into_response();
        }
    }
    CacheSuppressed((
        StatusCode::SEE_OTHER,
        [
            (header::LOCATION, pages.root_url().to_owned()),
            (header::SET_COOKIE, browser_session_clearing_set_cookie()),
        ],
    ))
    .into_response()
}
}
