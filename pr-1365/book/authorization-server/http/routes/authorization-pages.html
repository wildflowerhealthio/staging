While a request waits, the browser waits on a page this server serves, on its own origin, so the address bar names the server being approved. /oauth/authorize sends the browser to one of three pages beside it: the wait page while the Owner decides elsewhere, the consent card when this browser decides itself, the limited page when its session holds less than the app asks for. Two more pages are reached another way: the device page, where the Owner confirms a device’s code, and the pairing page, where a browser without a session asks for one.

The pages are static. Each is the same bytes for every request, and reads the request id or code from its own URL, so nothing a caller sends can reach the markup. What changes is answered by JSON routes beside them: the status poll the wait page drives, and the three calls the limited page makes. All of it is uncached, and all of it is locked down by the same security headers.

http::routes::oauth::pages

content_security_policy

A page loads only from this origin, talks only to this origin, and can’t be framed. The one thing that differs between pages is where their forms may go: the wait page has no form, and the React pages’ Sign out form posts here and is redirected on to the launcher.

The Content-Security-Policy of a page whose forms may submit to, and follow redirects to, form_targets (a form-action source list, NO_FORM_TARGETS for none). Everything a page loads (its scripts, stylesheets and fonts) comes from this origin, it can only talk back to it, and nothing may frame it. The top-level navigation to the client’s redirect is not a fetch, so connect-src doesn’t constrain it. A router builds it once and hands it to page_security_headers for each request.

Panics

When form_targets holds a byte a header value can’t, which a source list of keywords and origins never does.

#![allow(unused)]
fn main() {

    HeaderValue::try_from(format!(
        "default-src 'none'; script-src 'self'; style-src 'self'; font-src 'self'; \
         connect-src 'self'; base-uri 'none'; form-action {form_targets}; \
         frame-ancestors 'none'"
    ))
    .expect("a source list of keywords and origins is a valid header value")
}
}

page_security_headers

Every page and asset is checked for them by assert_locked_down.

The headers every file of a page carries: its content_type, its content_security_policy (built by content_security_policy), no Referer on anything it loads from or leaves for another origin, and no sniffing a type other than the one declared. The referrer policy is same-origin, not no-referrer: under no-referrer a browser sends a form POST with Origin: null, which the host’s cookie→bearer layer refuses, so the pages’ Sign out would fail.

#![allow(unused)]
fn main() {
pub(super) fn page_security_headers(
    content_type: &'static str,
    content_security_policy: &HeaderValue,
) -> [(HeaderName, HeaderValue); 4] {
    [
        (header::CONTENT_TYPE, HeaderValue::from_static(content_type)),
        (
            header::CONTENT_SECURITY_POLICY,
            content_security_policy.clone(),
        ),
        (
            header::REFERRER_POLICY,
            HeaderValue::from_static("same-origin"),
        ),
        (
            header::X_CONTENT_TYPE_OPTIONS,
            HeaderValue::from_static("nosniff"),
        ),
    ]
}
}

http::routes::oauth::wait_page

The wait page is where a browser waits while the Owner decides somewhere else: in the host’s popup, in a signed-in launcher, or on a consent card. Its script polls the status until the request is decided, then follows the redirect the poll hands back. That redirect is the only address off this origin the page ever leaves for. While the request is pending, the page also checks whether this browser has since signed in as the Owner and, if so, switches to the consent card beside it. Its three files are embedded as they are, with nothing interpolated; the script has no unit tests, and the Wait Page integration tests pin how its files are served.

router

The wait page’s routes, relative to the /oauth mount. The page references its assets as ../wait.js and ../wait.css, which resolve to these two siblings whatever prefix the authorization server is mounted under.

fn main() {
pub(crate) fn router() -> Router<Arc<AuthorizationServerState>> {
    let policy = content_security_policy(NO_FORM_TARGETS);
    let script_policy = policy.clone();
    let stylesheet_policy = policy.clone();
    Router::new()
        .route(
            "/authorize/{id}/wait",
            get(move || async move { wait_page(&policy) }),
        )
        .route(
            "/authorize/wait.js",
            get(move || async move { wait_page_script(&script_policy) }),
        )
        .route(
            "/authorize/wait.css",
            get(move || async move { wait_page_stylesheet(&stylesheet_policy) }),
        )
}
}

#![allow(unused)]
fn main() {
fn router_for<S: Clone + Send + Sync + 'static>(
    pages: &'static Dir<'static>,
    form_targets: &str,
) -> Router<S> {
    let policy = content_security_policy(form_targets);
    let consent_policy = policy.clone();
    let limited_policy = policy.clone();
    let device_policy = policy.clone();
    let pair_policy = policy.clone();
    Router::new()
        .route(
            "/authorize/{id}/consent",
            get(move || async move { page(pages, CONSENT_PAGE, &consent_policy) }),
        )
        .route(
            "/authorize/{id}/limited",
            get(move || async move { page(pages, LIMITED_PAGE, &limited_policy) }),
        )
        .route(
            DEVICE_PAGE_ROUTE,
            get(move || async move { page(pages, DEVICE_PAGE, &device_policy) }),
        )
        .route(
            "/pair",
            get(move || async move { page(pages, PAIR_PAGE, &pair_policy) }),
        )
        .route(
            "/assets/{*file}",
            get(move |Path(file): Path<String>| async move { asset(pages, &file, &policy) }),
        )
}
}

asset

An asset is cached for a year without revalidating, since Vite’s file names carry a hash of their contents and never change under a name. Anything but a script, a stylesheet or a font is a 404, even when the build holds it.

The hashed script, stylesheet or font file under pages’ assets/, cached as immutable, under policy, or 404.

#![allow(unused)]
fn main() {
fn asset(pages: &'static Dir<'static>, file: &str, policy: &HeaderValue) -> Response {
    let Some(content_type) = asset_content_type(file) else {
        return StatusCode::NOT_FOUND.into_response();
    };
    let Some(asset) = pages.get_file(format!("{ASSETS_DIR}/{file}")) else {
        return StatusCode::NOT_FOUND.into_response();
    };
    (
        [(header::CACHE_CONTROL, IMMUTABLE)],
        page_security_headers(content_type, policy),
        asset.contents(),
    )
        .into_response()
}
}

fn main() {
fn asset_content_type(file: &str) -> Option<&'static str> {
    match FilePath::new(file)
        .extension()
        .and_then(|extension| extension.to_str())
    {
        Some("js") => Some("text/javascript; charset=utf-8"),
        Some("css") => Some("text/css; charset=utf-8"),
        Some("woff2") => Some("font/woff2"),
        _ => None,
    }
}

AuthorizationStatus

Polling response for the wait page watching an authorization request as it moves from Pending toward approval or denial: where the request stands, and once it is decided, where to send the browser.

#![allow(unused)]
fn main() {
pub enum AuthorizationStatus {
    /// `{"status":"pending"}`: undecided and unexpired, whether it waits for
    /// the Owner or still sits on its browser's limited page. The wait page
    /// keeps polling.
    Pending,
    /// `{"status":"denied","redirect":…}`: the Owner declined, or the
    /// browser session the request was made in was revoked; the poll can't
    /// tell the two apart, so every denial reads as declined.
    Denied {
        /// Client callback URL carrying `error=access_denied`, an
        /// `error_description` and `state` for code-flow requests (RFC 6749
        /// §4.1.2.1) so the wait page can complete the flow. Always set: only
        /// code-flow requests are polled here.
        redirect: Option<String>,
    },
    /// `{"status":"approved","redirect":…}`: the request was approved and
    /// its code issued.
    Approved {
        /// Client callback URL carrying the redeemable `code` and `state`
        /// (RFC 6749 §4.1.2). The wait page follows it.
        redirect: String,
    },
    /// `{"status":"error","message":…}`: the request passed its expiry
    /// undecided, so it can't be decided any more. The wait page stops and
    /// shows the message.
    Error {
        /// What the wait page shows: "Authorization request expired".
        message: String,
    },
}
}

handle_authorization_status_request

A leaked request id collects nothing. The authorization status reader enforces who may read; the handler passes it the browser session the cookie carries.

Return the current status of the pending authorization request, including the final redirect URL once approved. The caller’s browser session (its __Host-browser_session cookie) is answered when the request was made in it, or when its grant covers wildflower/AuthorizationRequest.r and .u, the scopes that decide the request on the consent card. Any other caller, with another session or none, gets the same 404 as an unknown id, so a leaked request id can’t collect the code.

The answers, by where the request stands:

  • pending: 200 AuthorizationStatus::Pending;
  • pending past its expiry: 200 AuthorizationStatus::Error;
  • denied: 200 AuthorizationStatus::Denied, with the client’s access_denied callback;
  • approved: 200 AuthorizationStatus::Approved, with the client’s callback carrying the code;
  • unknown, or not readable by this caller: 404 AuthorizationRequestNotFound;
  • approved but with no code: 500 server_error, an invariant the store broke.

Only code requests are answered here; a device and a pairing have polls of their own.

The error side is axum::response::ErrorResponse because two error shapes share the handler: the Owner-surface AuthorizationServerError (its AuthorizationRequestNotFound 404 / logged 500) and the OAuth-shaped OAuthErrorResponse server_error — ? converts either through its IntoResponse.

#![allow(unused)]
fn main() {
pub(super) async fn handle_authorization_status_request(
    reader: Live<LiveAuthorizationStatusReader>,
    token_verifier: Live<LiveTokenVerifier>,
    headers: HeaderMap,
    Path(id): Path<String>,
) -> axum::response::Result<AuthorizationStatus> {
    let polling_browser_session =
        carried_browser_session(&token_verifier, &headers).map_err(|error| {
            InternalError::new("verify a browser session at /oauth/authorize/{id}", error)
        })?;
    let poller = polling_browser_session.and_then(|claims| {
        let grant = claims.granted();
        claims.sid.map(|sid| PollingBrowserSession { sid, grant })
    });
    let view = reader.status(&id, poller.as_ref(), Utc::now()).map_err(
        |error| -> axum::response::ErrorResponse {
            match error {
                AuthorizationStatusError::NotFound { id } => {
                    AuthorizationServerError::AuthorizationRequestNotFound { id }.into()
                }
                AuthorizationStatusError::ApprovedWithoutCode => {
                    OAuthErrorResponse::server_error("Authorization code missing").into()
                }
                AuthorizationStatusError::Store(error) => error.into(),
            }
        },
    )?;
    Ok(match view {
        AuthorizationStatusView::Pending => AuthorizationStatus::Pending,
        AuthorizationStatusView::Expired => AuthorizationStatus::Error {
            message: "Authorization request expired".to_string(),
        },
        // Build the client callback so the user-agent waiting at the client's
        // redirect_uri receives `error=access_denied`, an `error_description`
        // and `state`, and stops hanging. The poll can't tell an Owner's
        // decline from a revoked browser session, so every denial reads as
        // declined.
        AuthorizationStatusView::Denied {
            redirect_uri,
            client_state,
        } => AuthorizationStatus::Denied {
            redirect: Some(build_client_error_redirect_url(
                &redirect_uri,
                OAuthErrorCode::AccessDenied,
                REQUEST_DECLINED_DESCRIPTION,
                &client_state,
            )),
        },
        AuthorizationStatusView::Approved {
            redirect_uri,
            code,
            client_state,
        } => AuthorizationStatus::Approved {
            redirect: build_client_redirect_url(&redirect_uri, &code, &client_state),
        },
    })
}
}

http::routes::oauth::session_shortfall

A browser whose session holds less than an app asks for is told so on the limited page before anyone else is bothered. The page makes three calls on its own origin: read what the session lacks, go on, or cancel. Each answers only the browser session the request was made in; any other browser, with another session or none, gets the same 404 as an unknown id.

The two posts carry no body, so another page could send them as a simple request. What refuses one is the host’s cookie-to-bearer layer, which answers 403 to a write carrying the cookie from any origin but the server’s. Every answer is uncached, since a Continue may carry the app’s redirect with a code. The Session Shortfall integration tests hold all three.

requesting_browser_session

The browser session headers carry, and its sid, as the limited page’s calls are answered in it; the 404 an unknown request id gets when they carry none.

#![allow(unused)]
fn main() {
fn requesting_browser_session(
    token_verifier: &LiveTokenVerifier,
    headers: &HeaderMap,
    id: &str,
) -> Result<(VerifiedClaims, String), AuthorizationServerError> {
    let not_found = || AuthorizationServerError::AuthorizationRequestNotFound { id: id.to_owned() };
    let claims = carried_browser_session(token_verifier, headers)
        .map_err(|error| {
            AuthorizationServerError::infrastructure(
                "verify a browser session at the limited page",
                error,
            )
        })?
        .ok_or_else(not_found)?;
    let sid = claims.sid.clone().ok_or_else(not_found)?;
    Ok((claims, sid))
}
}

handle_session_shortfall_continue

The request takes the branch /oauth/authorize would have taken had the session held everything, and next_step_location builds the location, under /oauth/, since the page follows it from elsewhere. Any other failure renders as /oauth/authorize would render it (AuthorizeError).

Go on with request id although this browser’s session holds less than it asks for: issue a code under a standing grant that covers it, or else ask the Owner, on the consent card when this browser can decide it and on the wait page otherwise, with the request’s five minutes started again. The request spent from the authorization start limit when /oauth/authorize parked it, so going on spends nothing. This browser session’s later requests for the same app skip the limited page. A client disabled since the request parked ends it: the request is denied and the app is sent access_denied.

#![allow(unused)]
fn main() {
pub(super) async fn handle_session_shortfall_continue(
    code_authorization_starter: Live<LiveCodeAuthorizationStarter>,
    token_verifier: Live<LiveTokenVerifier>,
    headers: HeaderMap,
    Path(id): Path<String>,
) -> Result<Response, AuthorizationServerError> {
    let (_, sid) = requesting_browser_session(&token_verifier, &headers, &id)?;
    let next_step = code_authorization_starter.continue_past_session_shortfall(
        &id,
        &sid,
        generate_authorization_code(),
        Utc::now(),
    );
    let location = match next_step {
        Ok(next_step) => next_step_location(next_step, &format!("{OAUTH_MOUNT}/")),
        Err(AuthorizationStartError::Store(
            error @ AuthorizationServerError::AuthorizationRequestNotFound { .. },
        )) => return Err(error),
        // Cancelled between this Continue's acknowledgement and its fast-path
        // approval: no longer waiting here, like any other request that isn't.
        Err(AuthorizationStartError::RequestNotPending) => {
            return Err(AuthorizationServerError::AuthorizationRequestNotFound { id })
        }
        Err(error) => match AuthorizeError::from(error) {
            AuthorizeError::Redirect { location } => location,
            other => return Ok(other.into_response()),
        },
    };
    Ok(next_location(location))
}
}
