Wildflower, Read in Order

Grants

Covers authorization-server-rust/src/domain/capabilities/access/grants.rs

The Owner’s list of trusted apps shows every standing grant: what each app, or each device, was allowed, and when it was last used. Revoking a grant ends what was issued under it: the app’s live access tokens and its refresh families die with the consent, so no app holding offline_access outlives its revoked consent.

The access tokens die through the host’s revocation store, which keeps a per-subject epoch outside the grant store: a token issued before its subject’s epoch no longer verifies. A token’s subject is its app’s client_id, so the epoch, and with it the revoke, is per app, not per grant. The revocation store is reached through the Revocation port.

revoke

The tests record the subjects the revocation port is asked to bump, through a recording port.

Revoke the grant id: bump its client’s revocation epoch, killing its live access tokens, then delete the grant and expire the client’s refresh-token families in one write scope, so standing consent and standing credentials die together — the whole cascade, so no offline_access client outlives its revoked consent. Runs under this capability’s own Grant.d gate; the token-kill is part of revoking a grant, so it does not additionally require Token.d.

The one capability with two scopes: a read scope loads the grant for its client, the epoch is bumped, and a write scope deletes. The epoch lives on the revocation store, so its bump can’t sit inside this store’s write lock, and it goes first: a bump that over-revokes on a failed delete is recoverable (a retry finds the grant and finishes), while a delete that commits without its bump leaves live access tokens and a retry that answers 404.

The epoch and the families are per client, not per grant: revoking one of a client’s grants ends every access token and refresh-token family the client holds. Both concrete grant tables are hit (grant ids are UUIDs unique across them, so at most one deletes a row).

Errors

AuthorizationServerError::GrantNotFound when no grant has id, or it vanished between the read and the delete; a store or revocation-store failure.

#![allow(unused)]
fn main() {
pub(crate) fn revoke(
    &self,
    id: &str,
    now: DateTime<Utc>,
) -> Result<(), AuthorizationServerError> {
    let grant = self
        .store
        .read(|tx| tx.grant_by_id(id))?
        .ok_or_else(|| grant_not_found(id))?;
    self.revocation
        .revoke_subject_as_of_now(grant.client_id())
        .map_err(|e| {
            AuthorizationServerError::infrastructure("revoke_subject_as_of_now failed", e)
        })?;
    self.store.write(|tx| {
        let removed_code = tx.delete_authorization_code_grant(id)?;
        let removed_device = tx.delete_device_grant(id)?;
        if !(removed_code || removed_device) {
            return Err(grant_not_found(id));
        }
        tx.expire_refresh_token_families_for_client(grant.client_id(), now)
    })
}
}

Revoke kills the grant AND expires the client’s refresh-token families in one go: the family deadline is pulled back and its live token stamped consumed at the revoke instant, so standing consent and standing credentials die together.

#![allow(unused)]
fn main() {
fn revoke_also_expires_the_clients_refresh_families() {
    use crate::domain::refresh_token::{RefreshToken, RefreshTokenFamily};

    let store = FakeGrantStore::default();
    store
        .tx()
        .create_authorization_code_grant(&code_grant("g1", "client-a"))
        .unwrap();
    store
        .tx()
        .insert_refresh_token_family_row(&RefreshTokenFamily {
            family_id: "fam-1".to_owned(),
            client_id: "client-a".to_owned(),
            scopes: vec!["read".to_owned()],
            patient: None,
            issued_at: Utc::now(),
            expires_at: Utc::now() + chrono::Duration::days(90),
            authorization_code_hash: None,
            grant_id: Some("g1".to_owned()),
            sid: None,
        })
        .unwrap();
    store
        .tx()
        .insert_refresh_token(&RefreshToken {
            token_hash: "live".to_owned(),
            family_id: "fam-1".to_owned(),
            issued_at: Utc::now(),
            consumed_at: None,
        })
        .unwrap();

    let revoked_at = Utc::now();
    let revoker = GrantsRevoker::new(store, Arc::new(SubjectsRevoked::default()));
    revoker.revoke("g1", revoked_at).unwrap();

    assert!(
        revoker.store.tx().grant_by_id("g1").unwrap().is_none(),
        "grant gone"
    );
    let (_token, family) = revoker
        .store
        .tx()
        .refresh_token_with_family_by_hash("live")
        .unwrap()
        .expect("row kept for auditability");
    assert_eq!(family.expires_at, revoked_at);
}
}
