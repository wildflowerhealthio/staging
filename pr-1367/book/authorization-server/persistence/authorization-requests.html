The authorization requests live in three tables, by how a request is keyed. code_authorization_requests holds the code requests, keyed by id. user_code_requests holds the device requests and browser pairings, keyed by the poller’s secret, found by the user_code the Owner enters, and told apart by a flow column. Only this module knows those two flows share a table. session_widening_requests holds the session widenings, keyed by id.

A decision lands once. Every write of a transition is the flow’s guarded replace: one UPDATE of the whole row, guarded on the key and the status the request was read with, so of two transitions read from one row the first to land wins and the other matches nothing (the guarded replace). At most one pending request holds a user_code: a partial unique index holds it, and a request decided or claimed is outside the index.

A row is checked against its flow and status on the way in. Each table’s row type reads into the flow’s struct through one conversion, the one place the columns are held against the flow and status; the table’s CHECKs refuse the same rows on write. A row whose approval disagrees with its status, or that lacks a column its flow requires, fails the read as malformed rather than reading as absent.

The tests’ requests are built by the helpers on the Test Fixtures page.

db::authorization_requests::code_request_row

CodeAuthorizationRequestRow

One code_authorization_requests row, one field per column of the same name. Every column a CodeRequest always has is NOT NULL. The approval is granted_scopes and patient, set only while the request is approved; the table’s CHECKs hold it to that, and to a status the code flow has. No foreign key ties client_id to clients or sid to browser_sessions: an app trusted on first use has no clients row yet, and a session is pruned on its own schedule.

#![allow(unused)]
fn main() {
pub(super) struct CodeAuthorizationRequestRow {
    /// The primary key: the request's UUID, so every read and write by id is
    /// a key lookup. An authorization code names its request by it.
    pub(super) id: String,
    /// The client that made the request.
    client_id: String,
    /// The scopes the client asked for, as a JSON array.
    requested_scopes: JsonStrings,
    /// When the request started; the Owner prompt orders by it.
    requested_at: DateTime<Utc>,
    /// When the request stops waiting for a decision. The retention sweep
    /// deletes a row by it, whatever its status.
    expires_at: DateTime<Utc>,
    /// Where the request stands, as its wire string: `awaiting_limited_page`,
    /// `pending`, `approved` or `denied`. A replace lands only on a row still
    /// at the status it was read with. Expiry is read from `expires_at`, never
    /// stored here.
    status: RequestStatus,
    /// The approved scopes, as a JSON array: set exactly while `status` is
    /// `approved`.
    granted_scopes: Option<JsonStrings>,
    /// The patient the approval binds, if any; only ever set beside
    /// `granted_scopes`.
    patient: Option<String>,
    /// The redirect the client presented, which its code or error goes back to.
    redirect_uri: UrlText,
    /// The PKCE S256 challenge the code's redemption is checked against.
    code_challenge: String,
    /// The `state` the client sent, which its callback carries back.
    client_state: String,
    /// The browser session the request was made in, which its code is issued
    /// under.
    sid: String,
    /// The SMART App Launch `launch` value the request consumed; `NULL` for a
    /// plain OAuth request.
    launch: Option<String>,
    /// The patient the consumed launch binds, if any, which an approval must
    /// name.
    launch_bound_patient: Option<String>,
    /// The requested scopes a standing grant already covered when the request
    /// parked, as a JSON array; the consent card shows them ticked.
    pre_approved_scopes: JsonStrings,
    /// Whether the browser that made the request can decide it itself; raising
    /// the request for the Owner clears it.
    decidable_in_requesting_browser: bool,
}
}

db::authorization_requests::user_code_request_row

UserCodeRequestRow

One user_code_requests row, one field per column of the same name. A browser pairing keeps its browser’s name in device_name, the column the device page reads a requester’s name from. The approval is granted_scopes and patient, set only while the request is approved or claimed; the table’s CHECKs hold it to that, to a status these flows have, and a pairing to a name and no patient.

Two indexes on user_code serve the device page: a plain one for its lookups by the code the Owner types or confirms, and user_code_requests_pending_user_code_uidx, unique where status is pending, so at most one pending request holds a user code. Decided and claimed rows are outside it, so they may share a code with each other and with one pending request.

fn main() {
fn take_state<A>(
    &mut self,
    into_flow_approval: impl FnOnce(&Self, Approval) -> Result<A, AuthorizationServerError>,
) -> Result<PolledState<A>, AuthorizationServerError> {
    let approval = approval_from_columns(
        self.status,
        self.granted_scopes.take(),
        self.patient.take(),
        |problem| self.malformed(problem),
    )?;
    match (self.status, approval) {
        (RequestStatus::Pending, None) => Ok(PolledState::Pending),
        (RequestStatus::Denied, None) => Ok(PolledState::Denied),
        (RequestStatus::Approved, Some(approval)) => {
            Ok(PolledState::Approved(into_flow_approval(self, approval)?))
        }
        (RequestStatus::Claimed, Some(approval)) => {
            Ok(PolledState::Claimed(into_flow_approval(self, approval)?))
        }
        (status, _) => Err(self.malformed(&format!("is {status}, which its flow never is"))),
    }
}

approval_from_columns

The conversions read the approval through it.

The approval a row’s granted_scopes and patient columns hold: present exactly when status is approved or claimed, and a patient only beside granted scopes. Any other combination is malformed.

#![allow(unused)]
fn main() {
fn approval_from_columns(
    status: RequestStatus,
    granted_scopes: Option<JsonStrings>,
    patient: Option<String>,
    malformed: impl FnOnce(&str) -> AuthorizationServerError,
) -> Result<Option<Approval>, AuthorizationServerError> {
    let carries_approval = matches!(status, RequestStatus::Approved | RequestStatus::Claimed);
    match (granted_scopes, patient) {
        (Some(granted_scopes), patient) if carries_approval => Ok(Some(Approval {
            granted_scopes: granted_scopes.0,
            patient,
        })),
        (None, None) if !carries_approval => Ok(None),
        _ => Err(malformed(&format!(
            "is {status} but its approval columns disagree"
        ))),
    }
}
}

fn main() {
fn is_awaiting_owner(
    &mut self,
    consent_key: &ConsentKey,
    now: DateTime<Utc>,
) -> Result<bool, AuthorizationServerError> {
    let request = match consent_key {
        ConsentKey::DeviceCode { user_code } | ConsentKey::BrowserPairing { user_code } => self
            .pending_polled_request_by_user_code(user_code)?
            .map(AuthorizationRequest::from),
        ConsentKey::AuthorizationCode { id } => {
            self.code_request_by_id(id)?.map(AuthorizationRequest::Code)
        }
        ConsentKey::SessionWidening { id } => self
            .session_widening_request_by_id(id)?
            .map(AuthorizationRequest::SessionWidening),
    };
    match request {
        Some(request) if request.is_undecided_at(now) => {
            Ok(!self.is_client_disabled(request.client_id())?)
        }
        _ => Ok(false),
    }
}
}
