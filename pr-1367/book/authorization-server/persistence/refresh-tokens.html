Refresh Tokens

Covers authorization-server-rust/src/db/refresh_tokens.rs

Covers authorization-server-rust/src/db/refresh_tokens/tests.rs

A refresh family is two tables. refresh_token_families holds what every link in the chain shares, once per family: the app, the scopes, the patient, the deadline, the hash of the code that started it, the grant behind it, the browser session. refresh_tokens holds one row per link, keyed by the hash of the token; the token itself is never stored. A link’s family_id is a foreign key to its family, enforced, as the pool turns foreign_keys on for every connection, so no link can exist without its family.

Ending a family never deletes it. Each expiry below, for a replayed link, the app revoking its token, the Owner revoking a grant, or a replayed code, pulls the family’s expires_at back to the moment it ended and stamps its unspent link spent at the same moment. The rows stay, so a link presented later still resolves to its dead family and is refused for that reason. Only the retention sweep deletes, once a family has been dead long enough.

The family’s grant_id is a soft reference with no foreign key: revoking a grant deletes the grant and keeps its families. The family table is indexed on client_id and authorization_code_hash, which the bulk expiries match on, on sid, which the browser-session sweep asks about, and on grant_id; the link table on family_id. The methods that touch both tables run their two statements in a nested transaction, which inside a write scope’s BEGIN IMMEDIATE is a savepoint: both land or neither does.

The tests are in a file of their own, refresh_tokens/tests.rs, and each is shown under the primitive it holds. They draw families from arb_family and plant them with seed_family_with_token.

stamp_refresh_token_consumed_if_live

A false doesn’t say why: spent already, or never issued. consume_refresh_token asks has_refresh_token next to tell them apart.

The consumed_at IS NULL guard is the whole atomicity of the consume: a concurrent redeemer of the same live token loses the affected-row count and gets false.

#![allow(unused)]
fn main() {
fn stamp_refresh_token_consumed_if_live(
    &mut self,
    token_hash: &str,
    now: DateTime<Utc>,
) -> Result<bool, AuthorizationServerError> {
    let conn = &mut *self.conn;
    let affected = diesel::update(
        refresh_tokens::table
            .find(token_hash)
            .filter(refresh_tokens::consumed_at.is_null()),
    )
    .set(refresh_tokens::consumed_at.eq(now))
    .execute(conn)
    .map_err(|e| {
        AuthorizationServerError::infrastructure(
            "stamp_refresh_token_consumed_if_live failed",
            e,
        )
    })?;
    Ok(affected == 1)
}
}

expire_refresh_token_family

End a token family by pulling its expires_at back to now, and stamp its still-live token consumed at the same instant so no row in a dead family looks live. Used by reuse detection and by ClientTokenRevoker when a client revokes its own refresh token. Rows are kept (not deleted) so the lineage stays auditable and replayed tokens still resolve to their dead family. The consumed_at IS NULL guard keeps genuine consumption stamps intact.

#![allow(unused)]
fn main() {
fn expire_refresh_token_family(
    &mut self,
    family_id: &str,
    now: DateTime<Utc>,
) -> Result<(), AuthorizationServerError> {
    let conn = &mut *self.conn;
    conn.transaction(|conn| {
        diesel::update(refresh_token_families::table.find(family_id))
            .set(refresh_token_families::expires_at.eq(now))
            .execute(conn)?;
        diesel::update(
            refresh_tokens::table
                .filter(refresh_tokens::family_id.eq(family_id))
                .filter(refresh_tokens::consumed_at.is_null()),
        )
        .set(refresh_tokens::consumed_at.eq(now))
        .execute(conn)?;
        Ok(())
    })
    .map_err(|e: diesel::result::Error| {
        AuthorizationServerError::infrastructure("expire_refresh_token_family failed", e)
    })
}
}

Ending a family keeps its rows: its deadline moves to the moment it ended, its live token is stamped consumed then, a token redeemed earlier keeps its own stamp, and another family is untouched.

#![allow(unused)]
fn main() {
fn expire_family_pulls_deadline_back_and_stamps_the_live_token() {
    let store = SqliteGrantStore::open_in_memory().expect("open in-memory store");
    seed_family_with_token(
        &store,
        &sample_family("family-a", "client-1"),
        &sample_token("token-1", "family-a"),
    );
    store
        .write(|tx| tx.insert_refresh_token(&sample_token("token-2", "family-a")))
        .expect("insert token-2");
    let untouched = sample_family("family-b", "client-1");
    seed_family_with_token(&store, &untouched, &sample_token("other", "family-b"));
    // token-1 was genuinely redeemed before the revocation — its stamp
    // must survive the family kill untouched.
    let redeemed_at = Utc::now();
    assert!(store
        .write(|tx| tx.stamp_refresh_token_consumed_if_live("token-1", redeemed_at))
        .expect("consume"));

    let revoked_at = Utc::now();
    store
        .write(|tx| tx.expire_refresh_token_family("family-a", revoked_at))
        .expect("expire");

    // Rows are kept — the lineage stays auditable — with the family's
    // deadline pulled back to the revocation instant.
    let (redeemed_token, family) = store
        .read(|tx| tx.refresh_token_with_family_by_hash("token-1"))
        .expect("query")
        .expect("row present");
    assert_eq!(family.expires_at, revoked_at);
    assert_eq!(redeemed_token.consumed_at, Some(redeemed_at));
    // The live token is stamped at the revocation instant, so nothing in
    // a dead family looks live.
    let (live_token, _) = store
        .read(|tx| tx.refresh_token_with_family_by_hash("token-2"))
        .expect("query")
        .expect("row present");
    assert_eq!(live_token.consumed_at, Some(revoked_at));
    // The sibling family is untouched.
    let (other_token, other_family) = store
        .read(|tx| tx.refresh_token_with_family_by_hash("other"))
        .expect("query")
        .expect("row present");
    assert_eq!(other_family.expires_at, untouched.expires_at);
    assert_eq!(other_token.consumed_at, None);
}
}

The one place lineage is destroyed rather than expired in place — the counterpart to Self::expire_refresh_token_family, which keeps it readable. cutoff is the retention cutoff, not now; the window is the caller’s (domain::retention::purge_expired).
