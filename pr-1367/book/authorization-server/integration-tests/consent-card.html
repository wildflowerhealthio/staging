Consent Card

Covers authorization-server-rust/tests/integration/consent_card.rs

When the person at the browser is the Owner, there’s no one to wait for. /oauth/authorize sends a browser signed in as the Owner to the consent card, /oauth/authorize/{id}/consent, where the request is decided in place. Any other browser with a session goes to the Wait Page, and a browser without one goes to pairing.

The card decides through the same /authorization/oauth-consents/{id} API the host’s popup uses, on the browser session’s own token as its bearer. In the running server the host’s cookie-to-bearer layer presents that token for the card; these tests send it as the bearer themselves. Which page a request goes to is recorded on the CodeRequest as decidable_in_requesting_browser, and shown to the host on the OwnerPrompt.

This file’s own helpers are on the Test Fixtures page, with the shared ones.

a_browser_without_a_session_goes_to_pairing

A browser without a live browser session, whether it sends no cookie, a garbage one, a revoked session’s token or the token under another cookie name, is sent to pairing, and nothing is parked.

#![allow(unused)]
fn main() {
async fn a_browser_without_a_session_goes_to_pairing() {
    let (g, _host_owner_token, db) = spin_up();
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let revoked = signed_in_same_device_session_token(&g).await;
    revocation_store_handle(&db)
        .revoke_subject_as_of_now(
            wildflowerhealthio_authorization_server::BROWSER_SESSION_CLIENT_ID,
        )
        .expect("revoke the browser-session client's subject");

    for cookie in [
        String::new(),
        "theme=dark".to_owned(),
        "__Host-browser_session=not-a-token".to_owned(),
        format!("__Host-browser_session={revoked}"),
        // The same token under another name is no browser session.
        format!("browser_session={revoked}"),
    ] {
        let res = authorize_with_cookie(&g, &cookie).await;
        assert_eq!(res.status(), StatusCode::FOUND, "{cookie:?}");
        assert!(
            location_of(&res).starts_with("pair?next="),
            "{cookie:?} goes to pairing, got {}",
            location_of(&res)
        );
    }
    assert_eq!(owner_prompt(&db), None, "nothing was parked");
}
}

Approving on the card answers with the client’s redirect carrying a code and the client’s state, and a wait page left open on the request settles on the same redirect.

#![allow(unused)]
fn main() {
async fn approving_on_the_owner_s_bearer_sends_the_code_to_the_client_and_settles_the_wait_page() {
    let (g, _host_owner_token, db) = spin_up();
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let (same_device_session_token, request_id) = parked_on_the_card(&g).await;

    let res = decide(
        &g,
        &same_device_session_token,
        &request_id,
        "approve",
        r#"{"approvedScopes":["patient/Observation.rs","openid"],"patient":null,"acknowledgedRegistrationChange":false}"#,
    )
    .await;
    assert_eq!(res.status(), StatusCode::OK);
    let decision = body_json(res.into_body()).await;
    assert_eq!(decision["status"], "approved");
    let redirect = Url::parse(decision["redirect"].as_str().expect("a redirect")).expect("a URL");
    assert_eq!(
        redirect.as_str().split('?').next(),
        Some("https://app.example/cb")
    );
    let query: std::collections::HashMap<_, _> = redirect.query_pairs().into_owned().collect();
    assert_eq!(query.get("state").map(String::as_str), Some("xyz"));
    assert!(query.contains_key("code"), "{redirect}");

    // A wait page left open on the request settles on the same callback.
    let status = status_of(&g, &same_device_session_token, &request_id).await;
    assert_eq!(status["status"], "approved");
    assert_eq!(status["redirect"], decision["redirect"]);
}
}

a_scope_that_was_not_requested_is_not_granted

An approval can’t add a scope the app didn’t ask for: a hand-made approval naming an extra scope earns a token for the requested scope alone.

#![allow(unused)]
fn main() {
async fn a_scope_that_was_not_requested_is_not_granted() {
    let (g, _host_owner_token, db) = spin_up();
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let (same_device_session_token, request_id) = parked_on_the_card(&g).await;

    // The card can't add scopes; a hand-made approval that does gets only
    // what was requested.
    let res = decide(
        &g,
        &same_device_session_token,
        &request_id,
        "approve",
        r#"{"approvedScopes":["patient/Observation.rs","patient/Condition.rs"],"patient":null,"acknowledgedRegistrationChange":false}"#,
    )
    .await;
    assert_eq!(res.status(), StatusCode::OK);
    let decision = body_json(res.into_body()).await;
    let redirect = Url::parse(decision["redirect"].as_str().expect("a redirect")).expect("a URL");
    let code = redirect
        .query_pairs()
        .find(|(name, _)| name == "code")
        .map(|(_, code)| code.into_owned())
        .expect("a code");

    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::post("/oauth/token")
                .header("content-type", "application/x-www-form-urlencoded"),
            Body::from(format!(
                "grant_type=authorization_code&client_id=test-app&code={code}&\
                 code_verifier={CODE_VERIFIER}&redirect_uri=https%3A%2F%2Fapp.example%2Fcb"
            )),
        ))
        .await
        .expect("oneshot");
    assert_eq!(res.status(), StatusCode::OK);
    let token = body_json(res.into_body()).await;
    assert_eq!(token["scope"], "patient/Observation.rs");
}
}

the_consent_card_is_locked_down_and_uncached

The card is served on the request’s own path, under the wait page’s headers: scripts, styles, fonts and connections come only from this origin, forms submit only here and to the launcher’s origin, and the page can’t be framed. Its scripts, stylesheets and fonts are pinned by authorization_pages.rs’s unit tests against a build they define.

#![allow(unused)]
fn main() {
async fn the_consent_card_is_locked_down_and_uncached() {
    let (g, _host_owner_token, _db) = spin_up();

    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::get("/oauth/authorize/req-1/consent"),
            Body::empty(),
        ))
        .await
        .expect("oneshot");

    assert_eq!(res.status(), StatusCode::OK);
    let header = |name: &str| {
        res.headers()
            .get(name)
            .and_then(|value| value.to_str().ok())
            .unwrap_or_else(|| panic!("{name}"))
            .to_owned()
    };
    assert_eq!(header("content-type"), "text/html; charset=utf-8");
    assert_eq!(
        header("content-security-policy"),
        "default-src 'none'; script-src 'self'; style-src 'self'; font-src 'self'; \
         connect-src 'self'; base-uri 'none'; form-action 'self' https://launcher.test; \
         frame-ancestors 'none'",
        "its sign-out form posts here and follows the redirect to the launcher"
    );
    assert_eq!(header("referrer-policy"), "same-origin");
    assert_eq!(header("x-content-type-options"), "nosniff");
    assert_cache_suppressed(&res, "the consent card");
}
}
