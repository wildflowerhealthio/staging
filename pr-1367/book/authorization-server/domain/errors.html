The server says no in four vocabularies, one per audience:

  • AuthorizationServerError to the Owner’s UI on the /authorization surface, and from every operation when the store fails;
  • OAuthErrorCode to an app, as the error of an OAuth response;
  • AuthorizeRefusal to the person at the browser, or the app, when /oauth/authorize refuses a request;
  • TokenExchangeError to an app at /oauth/token, with the specific reason kept for the operator’s log.

None of them knows about HTTP. Each is a domain fact, and the HTTP layer decides the status and the body (Errors and Wire Shapes). The two that reach an app are built so that nothing from the request is echoed back: a code is one of a closed set, and a description is one of the server’s fixed sentences.

domain::authorization_server_error

AuthorizationServerError

The semantic variants are decided one layer up from the store, in the capabilities, so the SQLite adapter and the in-memory test fake speak only the port’s primitive contract, and the store produces nothing but Infrastructure. Display gives each variant a sentence for the logs.

The ways an authorization server domain operation can fail. The *NotFound variants are semantic, client-facing outcomes that are part of the wire contract (each renders as a structured JSON 404 keyed by the resource’s identifying field); Infrastructure is an opaque infrastructure failure rendered as a logged, empty 500. Its audience is the Owner’s UI on the /authorization surface, which acts on the semantic variants, and every operation when the store fails. Each semantic 4xx renders as JSON naming the variant in error, with the identifying field beside it, so the Owner’s UI can tell which thing went missing.

#![allow(unused)]
fn main() {
pub enum AuthorizationServerError {
    /// No pending, unexpired authorization-code consent has this id — the
    /// Owner-facing `/authorization/oauth-consents/{id}` surface's 404.
    OAuthConsentNotFound {
        /// The authorization request id the Owner's UI asked for.
        id: String,
    },
    /// No pending, unexpired device-code consent has this user code — the
    /// Owner-facing `/authorization/devices/{userCode}` surface's 404.
    DeviceConsentNotFound {
        /// The user code the Owner's UI asked for.
        user_code: String,
    },
    /// No standing grant has this id — the `/authorization/grants/{id}` 404.
    GrantNotFound {
        /// The grant id the Owner's UI asked for.
        id: String,
    },
    /// No standing browser session has this `sid` — the
    /// `DELETE /authorization/browser-sessions/{sid}` 404.
    BrowserSessionNotFound {
        /// The session id the Owner's UI asked to revoke.
        sid: String,
    },
    /// No registered client has this `client_id` — the
    /// `PATCH /authorization/clients/{clientId}` 404.
    ClientNotFound {
        /// The client the Owner's UI asked to change.
        client_id: String,
    },
    /// The Owner tried to disable an essential client — the
    /// `PATCH /authorization/clients/{clientId}` **409**. Disabling it would
    /// leave the Owner no way in (see
    /// `is_essential_client`).
    /// Nothing is written when it is raised.
    EssentialClient {
        /// The essential client the Owner tried to disable.
        client_id: String,
    },
    /// No authorization request has this id — the `/oauth/authorize/{id}`
    /// polling endpoint's 404, which the wait page's poll hears.
    AuthorizationRequestNotFound {
        /// The authorization request id the wait page polled.
        id: String,
    },
    /// No session widening the caller may see has this id — the Owner's
    /// `/authorization/session-widenings/{id}` 404 (none pending and
    /// unexpired), and the limited page's
    /// `POST /oauth/session-widenings/{id}/poll` 404 (none asked in this
    /// browser's session).
    SessionWideningNotFound {
        /// The session widening id the caller asked for.
        id: String,
    },
    /// The caller authenticated, but their token doesn't cover the scope(s) the
    /// `/authorization` operation requires — the surface's **403**. `missing_scopes`
    /// are the rendered scopes the caller must additionally hold. Raised when the
    /// [`Scoped`](wildflowerhealthio_scope_capabilities::Scoped) extractor rejects (via
    /// `From<MissingScopes>`), and when a consent approval's approver lacks one
    /// of the request's approval scopes (`wildflower/Grant.c` for a standing
    /// grant, `wildflower/Client.c` and `wildflower/Client.u` for a
    /// registration trusted on first use, a code request's resource scopes),
    /// which depend on the request and so are checked per call. Nothing is
    /// written when an approval raises it.
    InsufficientScope {
        /// The rendered scopes the caller lacks.
        missing_scopes: Vec<String>,
    },
    /// An approver tried to grant a client more than they themselves hold —
    /// the consent approve surfaces' **403**. `approver_missing_scopes` are the rendered
    /// scopes the approval would grant that the approver's own token does not
    /// cover ("you can't delegate more permission than you have"). Semantic and
    /// client-facing: the approver must step up (or narrow their approval).
    /// It renders as the same 403 body as
    /// [`InsufficientScope`](AuthorizationServerError::InsufficientScope).
    InsufficientApproverScope {
        /// The rendered scopes the approval would grant beyond the approver's
        /// own token.
        approver_missing_scopes: Vec<String>,
    },
    /// The Owner approved an authorization-code consent whose client is new to
    /// this authorization server (or whose redirect / scopes step outside its
    /// registration) without acknowledging that warning — the consent approve
    /// surface's **409**. Semantic and client-facing: the launcher must show the
    /// registration warning and send
    /// `acknowledgedRegistrationChange: true`. Nothing is written when it is raised.
    RegistrationNotAcknowledged {
        /// The authorization request the Owner approved.
        id: String,
    },
    /// The Owner approved an authorization-code consent whose SMART launch
    /// bound a patient, naming a different patient (or none) — the consent
    /// approve surface's **409**. Nothing is written when it is raised.
    LaunchPatientMismatch {
        /// The authorization request the Owner approved.
        id: String,
    },
    /// An infrastructure failure in the backing store (a lock, query, or
    /// mapping error) — opaque to clients: the HTTP layer logs `context` +
    /// `source` and answers an empty 500. The cause is captured as text so
    /// this type stays free of the store's database error types.
    Infrastructure {
        /// A fixed phrase saying what the store was doing when it failed.
        context: &'static str,
        /// The cause's `Display` text. Kept as text, not an error source, so
        /// no database error type reaches the routes.
        source: String,
    },
}
}

domain::oauth_error_code

OAuthErrorCode

A code from the closed set of OAuth error codes the authorization server’s JSON error surface may emit. Its AsRef<str>/Display impls (derived by strum from the snake_case variant names) yield the exact RFC wire value. Its audience is an app, as the error of an OAuth response: from /oauth/token, or on its callback redirect.

#![allow(unused)]
fn main() {
pub(crate) enum OAuthErrorCode {
    /// RFC 6749 §5.2 — the request is missing a required parameter, malformed,
    /// or otherwise invalid.
    InvalidRequest,
    /// RFC 6749 §5.2 — client authentication failed.
    InvalidClient,
    /// RFC 6749 §5.2 — the provided grant (authorization code, refresh token,
    /// device code) is invalid, expired, revoked, or does not match.
    InvalidGrant,
    /// RFC 6749 §5.2 — the authenticated client is not authorized to use this
    /// grant type.
    UnauthorizedClient,
    /// RFC 6749 §5.2 — the requested scope is invalid, unknown, or exceeds what
    /// the client may hold.
    InvalidScope,
    /// RFC 6749 §4.1.2.1 — the authorization server does not support obtaining an
    /// authorization code using this `response_type`. Surfaced on the
    /// authorization-endpoint redirect, never the JSON token surface.
    UnsupportedResponseType,
    /// RFC 6749 §5.2 — the server encountered an unexpected condition.
    ServerError,
    /// RFC 6749 §4.1.2.1 — the resource owner (or authorization server) denied
    /// the request, or it ended before it could be approved (its browser
    /// session ended, or its browser cancelled on the limited page).
    AccessDenied,
    /// RFC 8628 §3.5 — the device authorization is still pending the user's
    /// action; the client should keep polling.
    AuthorizationPending,
    /// RFC 8628 §3.5 — the client is polling faster than the permitted interval
    /// and must back off.
    SlowDown,
    /// RFC 8628 §3.5 — the `device_code` has expired and the device-flow
    /// authorization session is no longer valid.
    ExpiredToken,
}
}

domain::authorize_refusal

RFC 6749 §4.1.2.1 lets a refusal go back to the app only once its redirect_uri is trusted. Before that point, or for a redirect nobody has vouched for, the refusal is a local page in the browser. Either way the reason is the same sentence.

AuthorizeRefusal

Why /oauth/authorize refused a request: shown on the local page, or sent back to a trusted redirect as the error_description. Its audience is the person at the browser, or the app once its redirect is trusted. The local page is titled for the refusal, with Self::description as its body.

#![allow(unused)]
fn main() {
pub enum AuthorizeRefusal {
    /// The `redirect_uri` is not a well-formed URL, so there is nowhere
    /// trusted to send the refusal.
    InvalidRedirectUri,
    /// The `redirect_uri` is not `http` or `https`.
    InvalidScheme,
    /// The request comes from a client the Owner has disabled.
    DisabledClient,
    /// The `redirect_uri` is not on a server-defined registration. A client
    /// trusted on first use is never refused for this: its new redirect goes
    /// to the Owner instead.
    RedirectUriNotAllowed,
    /// `response_type` is not `code`.
    UnsupportedResponseType,
    /// `code_challenge_method` is not `S256`.
    UnsupportedCodeChallengeMethod,
    /// `code_challenge` is not a well-formed S256 challenge.
    InvalidCodeChallenge,
    /// `launch` names no launch this client may see: never minted, pruned
    /// after expiring, or another app's, which reads exactly like one that
    /// doesn't exist.
    LaunchUnknown,
    /// `launch` names this client's launch, which was consumed already.
    LaunchAlreadyUsed,
    /// `launch` names this client's launch, which is past its expiry.
    LaunchExpired,
    /// `aud` does not name this server's origin, its FHIR base.
    InvalidAudience,
}
}

description

Every sentence is a fixed string, never request input, and valid error_description text, so nothing an attacker sends is echoed back and no sentence breaks the redirect’s grammar. The tests check every sentence against the RFC’s grammar with a small predicate, including the three fixed sentences of the client callback.

The sentence saying why: the local page’s body, and the error_description when the refusal goes back to the client. Plain ASCII without " or \, as RFC 6749 §4.1.2.1 requires of an error_description.

#![allow(unused)]
fn main() {
pub fn description(self) -> &'static str {
    match self {
        AuthorizeRefusal::InvalidRedirectUri => {
            "The supplied redirect_uri is not a well-formed URL."
        }
        AuthorizeRefusal::InvalidScheme => "The supplied redirect_uri must use http or https.",
        AuthorizeRefusal::DisabledClient => "The supplied client_id has been disabled.",
        AuthorizeRefusal::RedirectUriNotAllowed => {
            "The supplied redirect_uri is not registered for this client."
        }
        AuthorizeRefusal::UnsupportedResponseType => {
            "The app asked for a kind of sign-in this server doesn't support."
        }
        AuthorizeRefusal::UnsupportedCodeChallengeMethod => {
            "The app's sign-in request uses a security method this server doesn't support."
        }
        AuthorizeRefusal::InvalidCodeChallenge => {
            "The app's sign-in request has a malformed security check."
        }
        AuthorizeRefusal::LaunchUnknown => "This launch isn't recognized. Open the app again.",
        AuthorizeRefusal::LaunchAlreadyUsed => {
            "This launch was already used. Open the app again."
        }
        AuthorizeRefusal::LaunchExpired => "This launch has expired. Open the app again.",
        AuthorizeRefusal::InvalidAudience => {
            "The app asked for a different server than this one."
        }
    }
}

domain::token_exchange_error

The app hears less than the log. The HTTP layer collapses the specific reasons a grant was refused onto a few generic descriptions (invalid_grant_description), so a response doesn’t say which check a code failed, and a refresh token presented by the wrong app reads exactly like an unknown one. Two reasons record what was done as well as what was found: a code that is unknown or already redeemed has revoked any refresh family minted from it, and a consumed refresh token presented again has revoked its whole family.

The token exchanger and the redemption proofs raise each variant, and their tests show them.

InvalidGrantReason

Why a grant presented at /oauth/token was refused as invalid_grant. The specific reason goes to the operator’s log; the app hears one generic description per family of reasons. The fields carry only what an operator needs to tell the cases apart — never the code, verifier, challenge, or token.

#![allow(unused)]
fn main() {
pub(crate) enum InvalidGrantReason {
    /// The authorization code is unknown or already redeemed — a possible
    /// replay; any refresh family minted from the code has been revoked.
    CodeNotFoundOrRedeemed,
    /// The code was issued to a different client.
    CodeClientMismatch {
        /// The client the code was issued to.
        code_client_id: String,
        /// The client that presented it.
        presented_client_id: String,
    },
    /// The presented `redirect_uri` is not the one the code was issued for.
    CodeRedirectMismatch {
        /// The redirect the code was issued for.
        code_redirect_uri: String,
        /// The redirect the redeemer named.
        presented_redirect_uri: String,
    },
    /// The code's lifetime has passed.
    CodeExpired {
        /// When the code stopped being redeemable.
        expires_at: DateTime<Utc>,
    },
    /// The PKCE `code_verifier` does not hash to the parked challenge.
    PkceMismatch {
        /// The client that presented the code.
        client_id: String,
    },
    /// No device request matches the `device_code` for this client: none
    /// exists, or it belongs to another client, which reads the same.
    DeviceRequestNotFound {
        /// The client that presented the `device_code`.
        presented_client_id: String,
    },
    /// Two polls raced for one approved device request; this one lost.
    DeviceCodeAlreadyRedeemed {
        /// The client the device request belongs to.
        client_id: String,
    },
    /// No live refresh token has this value.
    RefreshTokenNotFound,
    /// The refresh token belongs to a different client — answered exactly like
    /// not-found so a stranger can't probe validity.
    RefreshTokenClientMismatch {
        /// The client the family was issued to.
        family_client_id: String,
        /// The client that presented the token.
        presented_client_id: String,
    },
    /// The family's absolute deadline passed, or it was ended (revoked or
    /// replayed), which moves the deadline to that moment.
    RefreshTokenExpired,
    /// The browser session the family was minted under has been revoked, or
    /// no longer exists.
    RefreshTokenSessionRevoked {
        /// The family whose browser session ended.
        family_id: String,
    },
    /// The family began before its client's revocation epoch: bumping the
    /// epoch revoked every token the client held then.
    RefreshTokenClientRevoked {
        /// The family issued before the client's tokens were revoked.
        family_id: String,
    },
    /// A consumed refresh token was presented again — theft signal; the whole
    /// family has been revoked.
    RefreshTokenReplayed {
        /// The family that has been revoked.
        family_id: String,
        /// The client the family was issued to.
        client_id: String,
    },
    /// The token vanished between lookup and rotation.
    RefreshTokenVanished {
        /// The family the token was looked up in.
        family_id: String,
    },
}
}

TokenExchangeError

The ways a token exchange can fail. All but Issuance and Store are the caller’s fault and render as 400 with the matching RFC 6749 §5.2 / RFC 8628 §3.5 error code; those two are server-side. Its audience is an app at /oauth/token, and the operator’s log, which gets the specific reason. An AuthorizationServerError from the store becomes Store and a signing failure becomes Issuance, so the exchange flows can use ? on either.

#![allow(unused)]
fn main() {
pub(crate) enum TokenExchangeError {
    /// The authenticated client's registration does not allow this grant type
    /// (`unauthorized_client`).
    UnauthorizedGrantType,
    /// The PKCE `code_verifier` is not 43–128 characters (RFC 7636 §4.1) — an
    /// `invalid_grant`, not a malformed request.
    InvalidCodeVerifier,
    /// The presented `redirect_uri` does not parse (`invalid_request`).
    InvalidRedirectUri,
    /// The grant itself was refused (`invalid_grant`), for the given reason.
    InvalidGrant(InvalidGrantReason),
    /// RFC 8628 §3.5 `expired_token`: the device request is past its expiry,
    /// or was already claimed by an earlier poll that minted its token.
    ExpiredToken,
    /// RFC 8628 §3.5 `authorization_pending`: the device request still waits
    /// for the Owner; the device keeps polling.
    AuthorizationPending,
    /// RFC 8628 §3.5 `access_denied`: the Owner denied the device request.
    AccessDenied,
    /// RFC 8628 §3.5 `slow_down`: the device polled a pending request sooner
    /// than the advertised interval allows.
    SlowDown,
    /// The token could not be minted after the grant was accepted; the
    /// exchange's scope was rolled back with it, so nothing was consumed. A
    /// `server_error` 500.
    Issuance(AccessTokenIssuanceError),
    /// A store read or write failed: an empty 500, logged.
    Store(AuthorizationServerError),
}
}
