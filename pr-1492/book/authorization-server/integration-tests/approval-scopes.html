Wildflower, Read in Order

Approval Scopes

Covers authorization-server-rust/tests/integration/approval_scopes.rs

The Owner can approve anything. A paired browser, one whose browser session holds less than the Owner’s, may approve a request too, but only if it could create everything the approval creates. Those are the request’s approval scopes:

  • wildflower/AuthorizationRequest.u, because every approval decides a request.
  • wildflower/Grant.c, because a code or device approval records a standing grant.
  • Both wildflower/Client.c and wildflower/Client.u for a code approval for a client trusted on first use, because it creates or widens the client’s registration. It takes both whatever the row looks like when the approval lands, so an approval never turns on whether the row exists yet.
  • The resource scopes a code-flow request asks for, because the approval approves the request as asked and the approver must hold what it passes on.

A refused approval is 403 InsufficientScope, naming the scopes it lacks, and the request stays pending for the Owner. The same list is shown in three places, from one function (ApprovableScopes::missing_approval_scopes), so they never disagree: the approve call refuses on it (DelegatedScopes::clamp), the consent read reports it as missingApprovalScopes, and /oauth/authorize sends the browser to the Consent Card only when it lacks none, and to the Wait Page otherwise.

#![allow(unused)]
fn main() {
async fn an_approved_browser_approves_a_registered_app_within_its_own_scopes() {

        &db,
        "test-app",

    assert_eq!(body_json(res.into_body()).await["status"], "approved");
}
}

an_approved_browser_without_client_update_cannot_register_a_new_app

Registering a new app takes both client scopes: wildflower/Client.c alone is refused, and the refused approval registers nothing. A browser holding both then approves the same request.

#![allow(unused)]
fn main() {
async fn an_approved_browser_without_client_update_cannot_register_a_new_app() {
    let (g, _owner_token, db) = spin_up();
    // `test-app` is registered nowhere: the request is `new`.
    let approver =
        approved_browser_token(&g, &db, &approver_scopes_without("wildflower/Client.u")).await;
    let request_id = parked_request(&g, &db).await;

    let consent = get_oauth_consent(&g, &approver, &request_id).await;
    assert_eq!(
        consent["missingApprovalScopes"],
        serde_json::json!(["wildflower/Client.u"])
    );
    let res = approve_oauth_consent(&g, &approver, &request_id, APPROVE_REQUESTED.to_owned()).await;
    assert_refused_for_lacking(res, &["wildflower/Client.u"]).await;
    assert_eq!(request_status(&g, &db, &request_id).await, "pending");
    assert!(
        store_handle(&db)
            .read(|tx| tx.client_by_id("test-app"))
            .expect("read")
            .is_none(),
        "the refused approval registered nothing"
    );

    let registering_approver = approved_browser_token(&g, &db, APPROVER_SCOPES).await;
    let res = approve_oauth_consent(
        &g,
        &registering_approver,
        &request_id,
        APPROVE_REQUESTED.to_owned(),
    )
    .await;
    assert_eq!(res.status(), StatusCode::OK);
    assert_eq!(body_json(res.into_body()).await["status"], "approved");
}
}

an_approved_browser_without_grant_create_cannot_approve_a_device_request

The same holds for a device: a browser that can read and decide requests, but not create grants, is refused a device approval, because it records a standing device grant. The request stays pending.

#![allow(unused)]
fn main() {
async fn an_approved_browser_without_grant_create_cannot_approve_a_device_request() {
    let (g, _owner_token, db) = spin_up();
    seed_client_with_redirect(&db, "device-client", "https://app.example/cb", &["read"]);
    plant_device_request(
        &store_handle(&db),
        "device-client",
        "dev-1",
        &["read"],
        RequestStatus::Pending,
        Utc::now() + Duration::minutes(5),
    );
    let approver = approved_browser_token(
        &g,
        &db,
        &[
            "wildflower/AuthorizationRequest.r",
            "wildflower/AuthorizationRequest.u",
        ],
    )
    .await;

    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::post("/authorization/devices/WILD-FLWR/approve")
                .header("authorization", format!("Bearer {approver}"))
                .header("content-type", "application/json"),
            Body::from(r#"{"approvedScopes":["read"]}"#),
        ))
        .await
        .expect("oneshot");
    assert_refused_for_lacking(res, &["wildflower/Grant.c"]).await;
    assert_eq!(
        store_handle(&db)
            .read(|tx| tx.authorization_request_by_id("dev-1"))
            .expect("read")
            .expect("the request")
            .status(),
        RequestStatus::Pending,
    );
}
}

a_browser_session_lacking_a_requested_resource_scope_waits_for_the_owner

A browser holding every approval scope but the resource scope a registered app asks for can’t approve it as asked. Its session falls short of the request too, so /oauth/authorize sends it to the limited page first, and the Owner hears nothing yet. Continuing sends it to the wait page and raises the request for the Owner, and the consent read names the scope it lacks.

#![allow(unused)]
fn main() {
async fn a_browser_session_lacking_a_requested_resource_scope_waits_for_the_owner() {
    let (g, _owner_token, db) = spin_up();
    seed_client_with_redirect(
        &db,
        "test-app",
        "https://app.example/cb",
        &["patient/Observation.rs", "openid"],
    );
    let scopes_without_resource_scope = approver_scopes_without("patient/Observation.rs");
    let without_resource_scope =
        approved_browser_token(&g, &db, &scopes_without_resource_scope).await;
    narrow_browser_session_of(&db, &without_resource_scope, &scopes_without_resource_scope);
    let res = get_authorize(
        &g.router,
        &without_resource_scope,
        &authorize_query("test-app", REQUESTED_SCOPES),
    )
    .await;
    let request_id = limited_request_id(&res);
    assert_eq!(owner_prompt(&db), None);

    let location =
        continue_past_session_shortfall(&g.router, &without_resource_scope, &request_id).await;
    assert_eq!(location, format!("/oauth/authorize/{request_id}/wait"));
    assert!(matches!(
        owner_prompt(&db),
        Some(OwnerPrompt::AuthorizationCode {
            decidable_in_requesting_browser: false,
            ..
        })
    ));

    let consent = get_oauth_consent(&g, &without_resource_scope, &request_id).await;
    assert_eq!(
        consent["missingApprovalScopes"],
        serde_json::json!(["patient/Observation.rs"])
    );
}
}

asking_the_owner_raises_a_request_decidable_in_the_requesting_browser

“Ask the server’s owner” really raises the request: one made by a browser that could decide it there stops counting as decidable in that browser, so the host notifies the Owner, and it stays pending. A browser that can only read requests may ask; once decided, there’s nothing to ask about.

#![allow(unused)]
fn main() {
async fn asking_the_owner_raises_a_request_decidable_in_the_requesting_browser() {
    let (g, owner_token, db) = spin_up();
    let deciding_browser = approved_browser_token(&g, &db, APPROVER_SCOPES).await;
    let res = g
        .router
        .clone()
        .oneshot(build_request(
            Request::get(format!(
                "/oauth/authorize?{}",
                authorize_query("new-app", REQUESTED_SCOPES)
            ))
            .header(
                "cookie",
                format!("__Host-browser_session={deciding_browser}"),
            ),
            Body::empty(),
        ))
        .await
        .expect("oneshot");
    let location = location_of(&res);
    assert!(location.ends_with("/consent"), "{location}");
    let request_id = location
        .trim_start_matches("authorize/")
        .trim_end_matches("/consent")
        .to_owned();
    assert!(matches!(
        owner_prompt(&db),
        Some(OwnerPrompt::AuthorizationCode {
            decidable_in_requesting_browser: true,
            ..
        })
    ));

    let reading_browser =
        approved_browser_token(&g, &db, &["wildflower/AuthorizationRequest.r"]).await;
    assert_eq!(
        ask_owner(&g, &reading_browser, &request_id).await,
        StatusCode::NO_CONTENT
    );
    assert!(matches!(
        owner_prompt(&db),
        Some(OwnerPrompt::AuthorizationCode {
            decidable_in_requesting_browser: false,
            ..
        })
    ));
    let res = get_authorization_status(&g.router, &deciding_browser, &request_id).await;
    assert_eq!(res.status(), StatusCode::OK);
    assert_eq!(body_json(res.into_body()).await["status"], "pending");

    let res =
        approve_oauth_consent(&g, &owner_token, &request_id, APPROVE_REQUESTED.to_owned()).await;
    assert_eq!(res.status(), StatusCode::OK);
    assert_eq!(
        ask_owner(&g, &reading_browser, &request_id).await,
        StatusCode::NOT_FOUND
    );
}
}
